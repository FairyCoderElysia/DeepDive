## Summary

定义本作的**两条失败通道** —— **氯污染（猝死）**与**结垢（慢性）** ——
并保证它们**可诊断**（概念文档原话：**"失败必须可诊断，不能是暗算"**）。

## Overview

### 两条通道是**互补**的（概念文档已定）

> Key Dynamics #8 原话：**「这是本作唯一的慢性失败模式，与 #7 的猝死模式互补：
> 一个让你立刻报废，一个让你慢性失血。」**

| 通道 | 性格 | 机制 | 玩家学到什么 |
|------|------|------|--------------|
| **#7 氯污染** | **猝死** | 海水里的 Cl⁻ 在阳极被氧化成 Cl₂ → 混进 H₂ → 污染**立刻**出现 | 阳极材料不是风味选项，**它是氯通道的开关** |
| **#8 结垢** | **慢性** | Ca / Mg / S 在高温长停留下析出（CaSO₄ / Mg(OH)₂）→ 糊住换热面 → 效率持续下降 | **设备会老化，你要安排清理**（不是有人在催你） |

**化学事实已经定好了**（概念文档的元素分类表）：
> **硬度 = Mg / Ca → "结垢的来源"** · **硫酸盐 = S → "结垢的共犯（CaSO₄）"**

### 🚨 三条承重约束

**① 结垢必须是【连续速率】，不是批次。**
> **⚠️ 这里有一处概念文档的内部矛盾，必须以警告为准：**
> - **Key Dynamics #8 的措辞是批次的**：**「转化率一批比一批低」**（早先写的）；
> - **Core Mechanics #4 的警告是后来的**：**「结垢是连续累积速率，清洗是一段停机时间，
>   不要把"每批结算""清洗一次算一批"这类概念写进任何系统 GDD」**。
>
> **本系统以警告为准**：结垢是**连续累积量**，清洗是**一段停机时间**。
> （该矛盾已记录，见 Open Questions 下方。）

**② 污染是组成问题，结垢是设备状态 —— 两者【表示方式不同】。**
> 这不是实现细节，而是两条通道**互补**的机制原因（见 §Core Rules ①②）。
> **把两者都当成"一个污染值"来实现，是本系统最容易犯的错。**

**③ 失败必须可诊断，不能是暗算。**
> 概念文档原话（失败模式表标题）：**「失败模式（必须可诊断，不能是暗算）」**。
> → 玩家的失败必须能**归因到某个旋钮 / 某个接法**，否则它不可学习。

### 边界（它不是什么）

- **不是副产物的产生** —— 那是 **A2（副产物有哪些）** 与 **A3（实际产出多少）**。
- **不是纯度分级** —— 什么算"可用"属 **B3**（B2 说"污染从哪来、怎么传"，B3 说"它意味着什么"）。
- **不是诊断界面** —— 怎么把失败讲给玩家属 **B10**。
- **不是热力图** —— 怎么画属 **B12**。
- **不是灾难** —— 灾难（燃烧/爆炸）属 **B5**（B2 的两条通道是**慢性与污染**，不是灾难）。

**结垢的累积函数**：由温度与停留时间驱动（概念文档的元素分类已指明来源：硬度 Mg/Ca + 硫酸盐 S）。
**具体关系**属 Open Questions（要在 T1 用手感调）。

**清洗的具体机制**：一段停机时间（⑤）；**能否自动化见 ⑩**（T1 手动 / T2 自动）；
时长与代价属 Open Questions。

氯污染是否可逆（能不能洗掉）]`

## Player Fantasy
**方向：**「**我以为我在优化，其实我在给自己埋雷。**」

两条通道给的是**两种不同的痛**：

| 通道 | 痛在哪 |
|------|--------|
| **氯污染** | 痛在【**突然**】—— 你正在看别的地方，它已经发生了。而它其实早有征兆（参数在偏移带里） |
| **结垢** | 痛在【**不知不觉**】—— 产线一直在跑，只是每天慢一点点，直到某天你发现"怎么产量比刚建好时低这么多" |

**而两条都必须可诊断** —— 否则痛苦只是噪音（概念文档原话："不能是暗算"）。

**反例**：玩家看到产量低了，却不知道是**被氯弄脏了**还是**设备结垢了**。
**那两者的修法完全不同**（一个要分离、一个要清洗），**分不清就等于没有信息。**

### 澄清 1：为什么两条通道【互补】—— 机制原因，不只是设计标签

| | **氯通道** | **结垢通道** |
|---|---|---|
| 它是什么 | **组成**（物流里混进了别的东西） | **设备状态**（换热面上的积垢量） |
| 看得见吗 | **看得见**（在物流读数上） | **看不见物流**（必须另有呈现） |
| 发作方式 | **立刻**（产物降档 / 不可用） | **持续**（效率随积垢量下降） |
| 修法 | **分离 / 存贮 / 销毁**（B3、B4 的表） | **清洗**（一段停机时间） |

> **两者互补的原因正是"表示方式不同"**：
> 一个是**你的物质被弄脏了**，一个是**你的设备被糊住了** ——
> **它们攻击的是两样不同的东西，所以不可能被同一个办法解决。**
>
> ### ⚠️ 由此得到本系统最容易犯的错
> **把两者都实现成"一个污染值"**（例如给每台机器一个 0–100 的"脏度"）。
> **那会同时废掉两条通道的性格差异** —— 而且它会悄悄把"设备会老化"这件事
> 变成一个可以靠看物流发现的东西，**而它本来不该被发现**（那正是"慢性"的来源）。

### 澄清 2（F-B2-1）：**结垢的表现形式 = 部分输入【没被转化】** —— 而不是"变慢"

结垢糊住换热面 → 换热变差 → 反应**达不到该有的温度** → 转化率下降。
但"下降"有两读法，**差别很大**：

| 读法 | 后果 |
|------|------|
| **(a) 部分输入没被转化** | 产生**未反应物** → 它必须是"被接住的出口"之一（Key Dynamics #5）→ 而且它会与**回流**相互作用（Key Dynamics #2「循环死锁」） |
| (b) 转化变慢 | 只是慢，**没有额外物流** —— 简单，但少了一整条相互作用 |

**概念文档的原话是"糊住换热面 → 转化率下降"，所以取 (a)。**

> **这条让「结垢」与「回流」接上了**：结垢会让未反应物变多 → 玩家会想把它回流 → 而**回流过量会稀释到不反应**（#2）。
> **于是"清洗"与"回流比例"变成同一个决策的两面** ——
> 你可以靠清洗减少未反应物，也可以靠回流把它们捞回来，**而后者有它自己的失败模式。**
> **这正是概念文档要的那种"两条机制互相咬住"的设计。**


### States and Transitions
**只有【结垢】有状态** —— 氯污染是**组成**，不是状态（它由 B3 的档位去表达）。

| 结垢状态 | 含义 |
|----------|------|
| **净** | 积垢量 = 0（效率满） |
| **轻度** | 积垢 > 0；效率下降但仍可跑 |
| **重度** | 接近上限；产出显著变少（未反应物变多，见澄清 2） |
| **失效** | 积垢 = 100% → **停产**，必须清洗才能恢复（⑨） |

**迁移**：
```
净 --(高温/长停留, 连续累积)--> 轻度 --> 重度 --> 失效
任意态 --(清洗: 一段停机时间)--> 净
```

**⚠️ 必须与 A3 的机器状态区分**：
- **A3 的"饱和 / 灾难"是【反应层面】**（这一 tick 能不能反应）；
- **B2 的"积垢"是【设备层面】**（这台设备的老化程度）。
两者可以同时发生，**而且必须分别呈现**（见 §Visual/Audio）—— 把两者混成一个"机器状态"会让玩家无法归因。

## Formulas
> **本节原则（同 A3–A6）：B2 的公式大多是消费上游，不是新发明化学。**

### ① 氯污染的量 —— **不在此重定义**

用 A2 的 `offset_to_branch_ratio`：副产物占比 = δ × 系数。
**B2 只消费它**，并把它解释成"混进了什么"（组成）。

### ② 结垢累积（**连续积分**）

```
积垢(t) = 积垢(t-1) + 速率(温度, 停留时间) × dt        ← 连续速率，绝不是按批
```
> ⚠️ 概念文档 Key Dynamics #8 的原措辞是"一批比一批低"，**那是批次语言**，
> 与 Core Mechanics #4 的警告冲突。**本系统以警告为准**（见 §Overview ①）。

### ③ 积垢 → 转化率（并因此产生未反应物）

```
转化率 = f(积垢)                       ← 随积垢下降
未反应物 = 输入 × (1 − 转化率)          ← 【这部分必须被接住】（Key Dynamics #5）
```
**见澄清 2**：这是 (a) 读法 —— **不是"变慢"，而是"有东西没反应"**。

### ④ 清洗

```
清洗期间：停机 dt，不生产、不耗反应物；积垢 -> 0（或下降）
```

### ⑤ 污染传播

**由 A3 自然处理**（混合物进下一台机器）—— **B2 不需要新公式**。

### 两条由定位推出的性质

1. **它是唯一一个"两条机制互相咬住"的系统。**
   结垢 → 未反应物变多 → 玩家想回流 → **回流过量会稀释到不反应**（Key Dynamics #2）。
   → **"清洗"与"回流比例"是同一个决策的两面** —— 而这不是巧合，是澄清 2 那条读法的必然结果。
2. **它的两条通道攻击的是两样不同的东西**（你的物质 / 你的设备），
   → **所以它的呈现也必须分两路** ——
   **只做物流热力图会把"结垢"整个藏起来，而它恰恰是"不知不觉"的那一种痛。**

## Acceptance Criteria

**七条，每条都可独立检验。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **连续测试** | 结垢必须**随时间连续变化**（时间不推进则不变）—— **不得出现"按批跳跃"** |
| **2** | **通道分离测试** | 氯污染**不得**被实现成"另一个污染值"（它必须是**组成**）；结垢**不得**被实现成"组成"（它必须是**设备状态**）—— **两者互换即为失败** |
| **3** | **偏移带测试** | **偏移带内就必须出现污染**（不是只在越界时）—— A2 给 B2 的契约 |
| **4** | **可诊断测试** | 每条通道都必须能给出**可读归因**（哪个旋钮 / 哪个接法）—— 供 B10 直接使用 |
| **5** | **维护非时间限制测试** | 结垢**不得**产生"倒计时"式的压力（概念文档已注明：不是有人在催你） |
| **6** | **未反应物被接住测试** | 结垢导致的未反应物**必须进入物流**，且**必须能走"被接住"那套语义**（不得就地消失） |
| **7** | **可复原测试** | 失效后**清洗必须能恢复** —— 不得进入永久报废状态 |

> **第 6 条是澄清 2 的可测形式**，也是"结垢与回流咬住"的落点：
> **如果未反应物凭空消失，第 6 条会失败** —— 而它同时也违反了 P2。

## Visual/Audio Requirements

**B2 是"失败要被看见"的源头**，所以它必须让下游能表现**两种不同的痛**：

| 通道 | 表现需求（呈现属 B12/B10/B15） |
|------|-------------------------------|
| **氯污染** | 污染**已经在物流里**（组成问题）→ 可在**物流读数**上看见 |
| **结垢** | **看不见物流**（设备状态）→ **必须另有呈现**（换热面的状态、效率读数） |

> ⚠️ **这是两条通道"表示方式不同"在表现层的直接后果**：
> **只做物流热力图会把结垢整个藏起来** —— 而结垢恰恰是"不知不觉"的那一种痛。
> 并沿用 `art-bible` §3④：**形状优先于颜色**（饱和度预算只给了氧气与危险）。

## Game Feel

**方向：两种不同的痛**（见 §Player Fantasy）：
- **氯污染**痛在【突然】 —— 而它其实早有征兆（参数在偏移带里）；
- **结垢**痛在【不知不觉】 —— "怎么产量比刚建好时低这么多"。

**而两者都必须可诊断** —— 否则痛苦只是噪音。**B2 提供归因，B10 提供讲述。**

> ⚠️ **一条必须守住的边界**：概念文档已注明 **「维护周期 ≠ 时间限制」** ——
> 结垢是"你自己的设备会老化，你要安排清理"，**不是"有人在催你"**。
> **这个区别是手感上的**：前者是**你在管理**，后者是**你在被追**。

## UI Requirements

**B2 不直接产出 UI** —— 它是 **B10（诊断）**与 **B12（热力图）**的数据源。

它对 UI 的义务：
- **每一条通道的可读归因**：**哪个旋钮偏了 / 哪个接法错了**（B10 直接消费）
- **结垢必须能被看见**（它不是组成，**只做物流视图会漏掉它**）
- **两条通道要能被区分** —— 玩家必须能分辨"我是被氯弄脏了"还是"我的设备结垢了"，
  因为**两者的修法完全不同**（前者要分离，后者要清洗）

> 沿用全项目取向：**给可核对的细节，而不是给一个结论。**
> 例如不要只说「效率下降」，而要能回答「**是换热面结垢了、还是物流被污染了**」。
