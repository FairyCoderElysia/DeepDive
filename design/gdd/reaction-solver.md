# A3 · 反应求解器（Reaction Solver）

> **Status**: Draft（骨架 —— 已定的写清，未定的标 `[待定]`；我的建议标 `[待确认]`）
> **Category**: Core · **Layer**: Foundation · **Priority**: T1
> **Depends On**: **A1**（整数原子池 + 参数 schema）· **A2**（化合物组成 + 步骤表）
> **被依赖**: **8 个**（A5 · A6 · B2 · B4 · B5 · B7 · B10 · C3）
> —— 口径：`design/gdd/systems-index.md` 的 `Depends On` 列含 `A3` 的行数。**与 A1 并列最多。**
> **设计顺序**: 第 3 位

## Summary

**把 A1 的原子池与 A2 的步骤表，变成"这一 tick 实际发生了什么"** ——
算限制试剂、推进反应、按条件分支决定产出与灾难，并把结果**以整数**写回池。

## Overview

**它在"数据 → 世界"这条线上的位置**：
`A1 元素（数据）` · `A2 化合物与步骤（数据）` → **`A3 求解（算法）`** → `A5 工艺图（图的物流）`。
**A1/A2 存事实，A3 让事实发生。**

**为什么它是第二根承重柱**：它**有 8 个直接依赖者**（与 A1 并列最多）。
其中 **A5 的一句话最能说明它的地位** ——
> 「A5 工艺图与连续流求解 —— depends on: A3（**图求值的语义来自求解器**）」

也就是说：**玩家连出来的工艺图，其"求值语义"不是 A5 自己定的，而是 A3 定的。**
A3 若把"多台机器争同一池料"的语义定歪了，A5 会把它放大到整张图上。

**三条来自上游的承重约束（已经定了，不是本系统的自由）**：

| 来自 | 约束 |
|------|------|
| **A1** | **不得产生分数原子** —— 必须走 A1 的余数累加器（`rate_scaled` 指数化整数 / `floor` / 误差有界） |
| **A1** | **不得假设对账失败还能继续** —— ⑤ 是"拒绝该动作 + 对账锁" |
| **A2** | **不得假设一个产物只有一条路径**；**不得假设条件只有"对/错"两态**（三段区间 + 分支） |

**边界（它不是什么）**：
- **不是数据** —— 元素属 A1、化合物与步骤表属 A2。
- **不是工艺图** —— 图上的物流顺序与连续流属 **A5**（A5 依赖 A3，不是 A3 依赖 A5）。
- **不是灾难本身** —— A3 **触发**灾难（`disaster` 标记），灾难的后果与连锁属 **B5**。
- **不是氧经济** —— A3 产生"耗了多少氧"这个事实，把它变成一个经济体属 **B4**。
- **不是参数面** —— A3 用参数、产生代价事实；"代价如何呈现"属 **A6**。

`[待定 —— 还要写：被求解的粒度（一台机器？一个步骤？一张图？）· 每 tick 求解的规模与性能预算（
它与 B19 的关系）· 与 A5 的边界要划到什么程度]`

## Player Fantasy

`[待定 —— 方向：A3 兑现的是"世界会照你写的规则运行"这个承诺。
它的玩家感受应该是【"我的设计真的在按化学跑"】——
玩家改一个旋钮，能预见结果；遇到意外，能追到原因。
它不是"爽"也不是"紧张"，而是【可推演】。

反例方向：玩家调了旋钮但不知道会发生什么、也不知道为什么 —— 那就把 A3 变成了一台老虎机，
而老虎机与 P2「严谨是美感」直接冲突。]`

## Detailed Design

### Core Rules

`[待定 —— 草案，逐条待确认：]`

1. **求解粒度**：每台机器每 tick 求解其"当前步骤"。图上的顺序与连续流属 A5。`[待确认]`
2. **限制试剂**（A2 明确交给 A3）：对每条运行的步骤，实际推进量由
   `min over 输入项 (可用量 ÷ 需求量)` 决定 —— **这是"谁先耗尽"**。`[待确认]`
3. **整数量化**：推进量落到整数原子，**必须走 A1 的余数累加器**（每台机器、每种元素一个累加器）。
   **A3 不得自己发明一套舍入。**`[待确认]`
4. **分支判定**：按 A2 的 `offset_to_branch_ratio` 决定走主产物 / 副产物 / 灾难。
   **A3 只实现，不重新定义条件语义。**`[待确认]`
5. **抢料的确定性**（**承接 A1 的 Edge Case C**）：多台机器争同一池料时，**允许抢料、不保证谁赢**，
   但顺序必须**由可复现的机制决定**（例如每 tick 的轮转起点，**种子写入存档**）。
   **A3 就是这个机制的落地处。**`[待确认]`
6. **对账**：每 tick 结束后调用 A1 的守恒判定式；失败 → **拒绝该动作 + 进入对账锁**（A1 的 ⑤）。
   **A3 不得夹住差值、不得静默。**`[待确认]`
7. **灾难触发**：条件越界 → 置 `disaster` 并**照常配平地**产出（A2 已澄清灾难记录也受配平约束）；
   **后果与连锁归 B5**。`[待确认]`
8. **确定性**：同一存档 + 同一 tick 序列 → **结果逐位一致**（这是 A1 验收第 6 条在 A3 侧的兑现）。`[待确认]`

### States and Transitions

`[待定 —— 方向：机器/步骤的运行时状态（运行 / 饥饿 / 饱和 / 条件越界·灾难 / 对账锁），
以及它们之间怎么迁移。注意与 A1 的池状态区分：A1 的状态是"池"的，A3 的是"机器"的。]`

### Interactions with Other Systems

**上游 2 个**：A1（整数原子池 + 参数 schema）· A2（化合物组成 + 步骤表）。
**下游 8 个**（口径：`systems-index` 的 `Depends On` 列含 `A3` 的行数 = **8**）：

| 下游 | A3 承诺给它 | **它不得假设** |
|------|-------------|----------------|
| **A5** 工艺图与连续流求解 | **图求值的语义**（谁先取料、限制试剂、推进量） | 不得假设**可以自己定义求值顺序**；不得假设**A3 的语义是"公平"的**（A1 已定：允许抢料） |
| **A6** 参数与代价面 | 参数改变后**实际发生了什么**（含代价事实） | 不得假设**代价是线性的**；不得假设**参数只有"生效/不生效"两态** |
| **B2** 污染物与失败通道 | 副产物**是哪种、由哪个旋钮导致** | 不得假设**副产物只有一种**；不得假设污染**只在越界时才出现**（偏移带即出现） |
| **B4** 氧气经济 | 本 tick **实际消耗/产生多少氧** | 不得假设**氧只是原料**（它同时是生命维持）；不得假设**代价可以事后补算** |
| **B5** 灾难与失控 | **灾难触发信号**（`disaster`） | 不得假设**灾难是 A3 判定的后果**（A3 只触发，后果归 B5）；不得假设灾难**不消耗原子** |
| **B7** 百科 | 步骤/化合物**在什么条件下给出什么** | 不得假设**百科能自己算出可达路径**（那是 A3/A2 的活） |
| **B10** 诊断与反馈 | **可归因的失败**（哪个旋钮偏了、偏到哪一段） | 不得假设**失败可以事后重建**（若 A3 不记录归因，诊断就无从下手） |
| **C3** 飞船与零件 | 工艺的可求解性（零件的制造链能被求出来） | 不得假设**C3 可以绕过 A5/A3 自己算物料** |

`[待定 —— 需按 A1/A2 的做法逐条确认，尤其"不得假设"那一列]`

## Formulas

`[待定 —— 方向：]`
1. **限制试剂 / 实际推进量**：`推进量 = min over 输入项 (可用量 ÷ 需求量)`，取整数、走余数累加器。
2. **分支占比**：**不在此重定义** —— 用 A2 的 `offset_to_branch_ratio`（见登记册）。
3. **产出的整数化**：走 A1 的 `remainder_accumulator`。
4. **对账**：走 A1 的 `conservation_predicate`。
> **本节的原则：A3 的公式大多是"调用上游已登记的公式"，而不是新发明。**
> **凡是要新写的式子，都必须能被 A1 的守恒判定式接受。**

## Edge Cases

`[待定 —— 至少覆盖：输入不足（部分推进）· 输入为 0（机器空转）· 多种输入同时耗尽（限制试剂平局）·
抢料被抢空 · 条件在两段之间（A2 已要求导入期排除，但运行时仍需防御）· 灾难与对账锁同时发生（谁优先）·
同一 tick 内机器的处理顺序 · 余数累加器在机器被拆除时怎么办（残留的分数部分去哪）]`

## Acceptance Criteria

`[待定 —— 方向：]`
- **确定性测试**：同存档 + 同 tick 序列跑两遍 → **逐位一致**（含谁抢到料）
- **限制试剂测试**：构造"两种输入、其中一种先耗尽"的场景 → 必须由正确的那一种限制推进
- **整数测试**：任何输出都必须是整数原子；累加器残留必须 ∈ [0, SCALE)
- **守恒测试**：每 tick 通过 A1 的守恒判定（整数比较、无容差）
- **对账拒绝测试**：注入一次不守恒 → 必须拒绝该动作 + 进入对账锁（不得夹住、不得静默）
- **分支可归因测试**：副产物必须能回答"由哪个旋钮导致"（B10 的前提）
- **灾难配平测试**：`disaster` 触发时产出仍必须配平（A2 已澄清）
