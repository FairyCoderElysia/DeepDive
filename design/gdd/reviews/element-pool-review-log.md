## Phase 3 — 一致性与可实现性

### 判定标准只有一句
> **照原文实现，程序员需不需要自己替设计师做决定？**

### 查出 4 处，**全部已修**（见 commit `e1d799b`）

| # | 问题 | 修法 |
|---|------|------|
| **F-A1-1** 🔴 | §Formulas 写「全程整数运算」，却把公式写成 `需求 = 分数原子数 × SCALE` —— **"分数原子数"若来自 float 速率，这一步就把浮点请回来了**（正是决策 ① 要根除的） | **速率也必须指数化整数**：`rate_scaled` 单位「原子 × SCALE / tick」，`d = rate_scaled` 直接相加，**全程无浮点乘法**。理由写进文件，防后人"为省事"改回 |
| **F-A1-2** 🔴 | §Core Rules ① 只说"饱和时拒绝再增 + 告警"，**没说上游那股流怎么办** | 用户拍板：**上游阻塞 + 告警**。并写明反例 —— **绝不丢弃：丢弃等于物质凭空消失、直接违反 P2** |
| **F-A1-3** 🟡 | 缺元素符号"报错并记录" —— **记录到哪没写** | 须落在**玩家可见的诊断面板 + 存档**（只写日志等于玩家永远看不到） |
| **F-A1-4** 🟡 | 对账锁的"**一次**不守恒"**没定义什么叫一次** | 「一次」= **一个 tick 内的一次搬运动作**（可被拒绝的最小单位） |

> **F-A1-1 值得单独记一笔**：它是**本文件自己写出来的自相矛盾** —— 口号（全整数）与公式（含浮点乘法）不一致。
> **这类"口号与公式打架"的错，比单纯漏写更难发现**，因为两句话分开看都成立。

### 一句话留给 28 个下游
**本 GDD 立下的两个形状可以照抄**：
1. **旋钮表**（§Tuning Knobs A：旋钮名 / 单位 / 范围 / 默认值 / 谁消费）
2. **契约表**（§Interactions：**承诺 / 不得假设** 两列 —— **后者比前者更重要**，集成 bug 几乎都出在那里）

**但要照抄的是"形状"，不是"结论"** —— 每个系统自己的数字与契约必须自己推一遍。
