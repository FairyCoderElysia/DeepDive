## Summary

定义**失控之后的后果**：灾难怎么发生、会波及什么、以及**玩家怎么从中恢复**。
它是 P2「严谨是美感」与 P5「无时限」**吵出来的那个设计**。

## Overview

### 它是两条支柱吵出来的东西（概念文档原话）

> **「P2 的严谨会惩罚玩家 ↔ P5 的无时限要求不劝退 →「灾难可复原」就是这两条吵出来的设计。」**

**所以 B5 的存在理由不是"加难度"，而是"让惩罚与不劝退同时成立"。**

### 灾难的链条（概念文档已定）

```
条件不对 --> 意料之外的产物 --> 原本的产物发生变化 --> 【严重时：失控放热 / 燃烧 / 爆炸】
```

**注意 B5 只管最后那一段** —— 前三段归 A2/A3/B2/B3。**B5 是链条的末端，不是起点。**

### 三条承重约束

**① 灾难必须【可复原】**（概念文档 line 208，原话）：
> **「灾难必须可复原 —— 重建成本低，并提供隔离、泄压、旁通这类"工程上的保险"给玩家用。
> 失败是教育，不是惩罚（这是 P2 与 P5 的直接约束）。」**

**② 灾难必须【壮观】**（同样是原话）：
> **「失控放热、爆罐、燃烧必须有一眼认得出的视觉与音效签名 —— 它们是"严谨是美感"的可见证据」**
> —— 争"让爆炸安静点别吓人" vs "让它有辨识度且不可忽略" → **选后者**。

**③ B5 只管【后果】，不管【触发】。**
> A3 给 B5 的契约：**「不得假设灾难是 A3 判定的后果（A3 只触发，后果归 B5）」**。
> 且 **A2 已澄清：灾难记录同样受配平约束** —— `disaster: true` 只是**效果标记**，
> **原子侧照常配平**（真实化学里灾难本身就是反应：燃烧耗 O₂、生成氧化物）。
> → **B5 不得让物质凭空消失**（那是 P2 的底线）。

### 边界（它不是什么）

- **不是触发条件** —— 那是 **A3**（越界 → 置 `disaster`）与 **A2**（分段语义）。
- **不是代价的极端值** —— A6 给 B5 的契约明写：**灾难是独立的通道，不是"最贵"**。
- **不是诊断界面** —— 怎么讲给玩家听属 **B10**。
- **不是音效** —— 怎么做出来属 **B15**（B5 只定义"必须有一个签名"）。
- **不是慢性劣化** —— 结垢属 **B2**（那是"慢性失血"，不是灾难）。

**灾难是否有前兆？** 倾向**分两种**：热失控类**有**（温度在爬，玩家看得见）；
猝发类**没有**（但它的成因在更早的偏移里 —— 见 B2 的"氯污染是猝死"）。列入 Open Questions。

**是否连锁？** ✅ 已定：**会**，且**可被工程保险挡住**（③）。
**但传播只能走物流、不能走空间** —— 见澄清 3。

**工程保险是造的还是自动的？** ✅ 已定：**玩家造的**（④）。

**灾难后设备是毁还是可修？** ✅ 已定：**可修，成本随严重度**（⑤）。

## Player Fantasy
**方向：**「**我早就知道会这样 —— 而我没有管它。**」

灾难的美感来自"**它是可预见的**"：玩家看着温度爬升、知道越界会出事、
**却没有去处理** —— 然后它真的出事了。

**那才是"严谨是美感"**：不是随机惩罚，而是**你自己写下的规则按你自己的方式兑现了**。

**反例**：灾难像一个随机事件砸下来。**那就把它变成了运气** —— 而 P2 的整个卖点就是"不是运气"。

**另一条必须守住的边界**：**"壮观"不等于"惩罚重"**。
概念文档把它们**分成两条**（"灾难要壮观" 与 "风险 #5：复原成本"）——
**前者是感官问题（要够响够大），后者是数值问题（要能爬起来）。两者不能互相代替。**

### 澄清 1：**"会连锁"是从概念文档的措辞里推出来的**（不是我们另加的设计）

概念文档说：
> **「灾难必须可复原 —— 重建成本低，并提供【隔离、泄压、旁通】这类"工程上的保险"给玩家用。」**

**保险的存在，本身就意味着有一个需要被保的东西** —— 而那东西就是**连锁**：

| 保险 | 它管的是 |
|------|----------|
| **隔离** | **别让它传过去**（切断传播） |
| **泄压** | **别让它炸**（释放压力） |
| **旁通** | **别让它堵死整条线**（绕过受损段） |

> **若灾难不连锁，这三样都没有对象** —— 它们会变成三个没有用处的装饰件。

**所以"会连锁"不是我们发明的机制，而是那句"提供工程保险"的必要前提。**

### 澄清 2：④ 与 ⑤ 合起来，把"复原成本"从一个刻度变成了【玩家的决策】

- **④ 保险是玩家造的** → 肯投资的人，灾难更便宜；
- **⑤ 修复成本随严重度** → 灾难越重，修得越贵。

**合起来的后果**：**"我的产线该不该上保险"变成一个真正的风险/收益决策** ——
而这正是风险 #5 那个刻度（"太便宜失去重量、太贵劝退"）能被人为调节的地方：
**不是靠全局调参，而是靠玩家自己的投资。**

> **这比"改一个全局系数"好得多**：它让同一个数值下，**谨慎的玩家与鲁莽的玩家承受不同的后果** ——
> 而"承担自己选择的后果"正是 P2 与 P3 的交汇点。

### 澄清 3（F-B5-1）：**连锁只能走【物流】，不能走【空间】** —— 因为本作没有空间模型

概念文档说"**爆罐**" —— 那个词听起来很**空间**（炸到旁边的罐子）。**但本作没有空间模型**：

> Core Mechanics #4 明写：**「管网是节点 + 边的逻辑图，不是逐 tile 模拟」**。

**所以"连锁"的传播只能是：**

| 传播方式 | 能不能用 | 为什么 |
|----------|----------|--------|
| **沿物流传播**（图上的边） | ✅ **这一条** | 图就是本作的"空间" |
| 沿空间邻接传播（旁边就是受害者） | ❌ **做不到** | **没有"旁边"这个概念** —— 机器之间只有"连没连" |

### 而这恰好让"保险三件套"全部说得通

| 保险 | 它在图的哪一层 |
|------|----------------|
| **隔离** | **在【边】上断流** —— 别让失控的物流传过去 |
| **旁通** | **绕开受损的【节点/边】** —— 主线还能跑 |
| **泄压** | **【设备】自身的属性** —— 别让它炸 |

> **三者都是【图 / 设备】层面的事，一个都不需要空间。**
> **所以"会连锁"这个决定（③）与"没有空间模型"这件事不冲突** —— 前提是**你别把它实现成空间传播。**

**⚠️ 表现与机制要分开**：**表现上可以做得像"炸到了旁边"**（那正是"壮观"要的），
**但机制上必须是"失控的物料沿边流到了下游"** —— 否则实现者会去找一个不存在的空间模型。


### States and Transitions
**灾难是一次【事件】，不是状态** —— 但它会留下**状态**。

| 事后状态 | 含义 |
|----------|------|
| **已隔离** | 玩家用隔离阀切断了传播 |
| **受损** | 设备还在，但需修（修复成本随严重度，⑤） |
| **已修复** | 恢复可运行 |

**⚠️ 必须与另外三种"机器停下来了"区分清楚**（它们的原因与恢复手段完全不同）：

| 谁 | 为什么停 | 怎么恢复 |
|----|----------|----------|
| **A3 对账锁** | 守恒失败（状态不可信） | 玩家确认 + 重算基线 |
| **B2 结垢失效** | 慢性积垢到 100% | **清洗**（一段停机时间） |
| **A5 阻塞** | 产不出去（下游满 + 罐满） | 腾出容量 |
| **B5 灾难** | **失控**（越界导致） | **修**（成本随严重度）+ 隔离/旁通 |

> **四种"停"在界面上必须可区分** —— 否则玩家看到"我的机器停了"，
> **而四种停法的修法完全不同**（B10 的前提）。

**另有一条已定的优先级**（A3 的 §States）：**对账锁优先于灾难** ——
守恒失败意味着状态不可信，此时再跑灾难逻辑只会产出**不可信的灾难**。

## Formulas
> **本节原则（同 A3–A6）：B5 消费上游，不重定义触发条件。**

### ① 灾难的后果强度 —— **不在此重定义**

由 **A6** 的越界段形状给出（**灾难不是代价的极端值** —— 它是独立通道，见 ⑦）。

### ② 连锁的传播（**沿边，不沿空间**）

```
失控节点 --沿出边--> 下游节点（若未隔离）
隔离生效 -> 该边断流，传播中止
```
**见澄清 3**：本作没有空间模型，**"旁边"不存在**。

### ③ 修复成本（风险 #5 的那个刻度）

```
修复成本 = f(严重度)          ← 一个连续旋钮，不是"活/死"开关（⑤）
```
**并且它受玩家投资影响**：上了保险的产线，灾难的**赔偿上限**更低（澄清 2）。

### ④ 无随机性

```
同存档 + 同操作序列  =>  同一次灾难（必然复现）      ← ⑨
```

## Edge Cases
| 边界 | 行为 | 依据 |
|------|------|------|
| **连续两次灾难** | 允许；但第二次的严重度**不得无上限叠加放大**（那会破坏可复原） | ① |
| **灾难与对账锁同时发生** | **对账锁优先** —— 守恒失败意味着状态不可信，此时跑灾难逻辑只会产出不可信的灾难 | A3 的 §States |
| **孤岛设备上的灾难** | 连锁**无处可传**（没有下游）→ 就地结束 | ③ + 澄清 3 |
| **灾难沿环传播** | 必须能**终止**（与 A5 的环处理一致，不得死循环） | A5 的纪律 |
| **保险生效时，灾难算不算"发生"** | **算** —— **保险改变的是【后果】，不是"有没有发生"**（否则 B10 的因果链就断了） | ⑩ + B10 的契约 |
| **玩家在灾难期间操作** | 允许（**无时限、不暂停、不惩罚操作速度**）；但**隔离必须及时才有效** | P5 |
| **灾难后设备是"坏了"还是"没了"** | **仍存在、需修**（⑤）—— 不是"活/死"开关 | ⑤ |

**上游 2 个**：A6 · A3。

### 两条由定位推出的性质

1. **它是唯一一个专门处理【事后】的系统。**
   A1–A6 / B2 / B3 / B4 / B6 都在处理"**怎么让它跑起来**"，
   **而 B5 处理"它崩了以后怎么办"** —— 所以它的产出不是数据也不是规则，而是**一条恢复路径**。
2. **它是三条支柱交汇的地方**（比任何其它系统都多）：
   - **P2**（严谨必须真惩罚）→ 灾难必须真的疼；
   - **P5**（无时限不劝退）→ 但必须能爬起来；
   - **P3**（工艺属于玩家）→ **保险是玩家造的**（④）→ **后果由玩家自己的投资决定**。
   → **"灾难可复原"之所以是这三条吵出来的设计，就因为它同时被三条约束着。**

## Tuning Knobs

| 项 | 范围 | 默认（暂定） | 说明 |
|----|------|--------------|------|
| **修复成本的严重度曲线** | — | 待定 | **风险 #5 那个刻度**：太便宜失去重量、太贵劝退 |
| **连锁的传播强度** | 沿边衰减 / 全量 | 待定 | 决定"一次失误能带走多少" |
| **隔离的效果** | 0–1 | 待定 | 能挡住多少传播 |
| **泄压的效果** | 0–1 | 待定 | 能降低多少严重度 |
| **旁通的效果** | — | 待定 | 能否让主线在被绕开时仍跑 |
| **前兆时长**（热失控类） | 秒 | 待定 | 决定"可预判"有多早 |

> ⚠️ **边界**：触发阈值属 **A3** · 代价形状属 **A6** · 慢性劣化属 **B2** ——
> **B5 只定义"后果与复原"。**

## Acceptance Criteria

**七条，每条都可独立检验。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **可复原测试**（核心） | 任意灾难之后，**必须存在一条回到可运行状态的路径**，且代价**有限** |
| **2** | **守恒测试** | 灾难**不得让原子凭空消失**（A2 已澄清：原子侧照常配平） |
| **3** | **独立通道测试** | 灾难**不得**被实现成"代价面最贵的那一档"（A6 的契约） |
| **4** | **可辨识测试** | **不同灾难类型必须可区分**（视觉与音效签名各异） |
| **5** | **可诊断测试** | 灾难必须能给出**因果链**（从哪个条件偏移开始、经过哪些环节）—— 供 B10 |
| **6** | **非随机测试** | 同存档 + 同操作序列 → **灾难必然复现**（不得有随机性） |
| **7** | **沿边传播测试（F-B5-1）** | 连锁**必须沿图的边传播** —— **不得依赖任何空间邻接**（本作没有"旁边"） |

> **第 7 条是澄清 3 的可测形式**：它保证实现者不会去找一个不存在的空间模型。
> **并且它解释了"隔离/旁通"为什么是有效的** —— 它们作用在边与节点上，而连锁也走边与节点。

## Visual/Audio Requirements

**概念文档已定一条硬要求**：
> **「灾难要壮观：失控放热、爆罐、燃烧必须有一眼认得出的视觉与音效签名」** ——
> 争"让爆炸安静点别吓人" vs "让它有辨识度且不可忽略" → **选后者**。

**B5 的义务是把这条变成可实现的**：**不同灾难类型必须可区分**（不能只有一个通用爆炸），
且**签名必须与"代价陡升"区分开**（A6 的契约：灾难不是代价的极端值）。

> ⚠️ 并沿用 `art-bible` §3④：**形状优先于颜色**（饱和度预算只给了氧气与危险 ——
> 而灾难**正好是"危险"，所以它可以、也应该用饱和度**。这是 art-bible 里少数明确允许高饱和的场合之一）。

## Game Feel

**方向：**「**我早就知道会这样 —— 而我没有管它。**」

灾难的美感来自"**它是可预见的**"：玩家看着温度爬升、知道越界会出事、**却没有去处理** —— 然后它真的出事了。
**那才是"严谨是美感"**：不是随机惩罚，而是**你自己写下的规则按你自己的方式兑现了**。

**反例**：灾难像一个随机事件砸下来。**那就把它变成了运气** —— 而 P2 的整个卖点就是"不是运气"。

**另一个必须守住的边界**：**"壮观"不等于"惩罚重"**。
概念文档把它们分成两条（`灾难要壮观` 与 `风险 #5 复原成本`）——
**前者是感官问题（要够响够大），后者是数值问题（要能爬起来）。两者不能互相代替。**

## UI Requirements

**B5 不直接产出 UI** —— 它是 **B10（诊断）**与 **B15（音频）**的数据源。

它对 UI 的义务：
- **因果链**（从哪个条件偏移开始、经过哪些环节）—— 这是"失败是教育"的前提
- **灾难类型的可辨识标识**（不只是"出事了"）
- **复原路径的可见性**（"我现在该做什么才能恢复"）

> 沿用全项目取向：**给可核对的细节，而不是给一个结论。**
> 例如不要只说「设备损毁」，而要能回答「**是因为哪个旋钮偏了多少、从什么时候开始失控的**」。
