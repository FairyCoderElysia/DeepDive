# A6 · 参数与代价面（Parameters & Cost Surface）

> **Status**: **Approved**（2026-10-02 评审通过 —— 见 `design/gdd/reviews/parameters-cost-surface-review-log.md`）
> **Category**: Core · **Layer**: Foundation · **Priority**: T1
> **Depends On**: **A3**（反应求解器 —— 代价是"实际发生了什么"的聚合）
> **被依赖**: **5 个**（B2 · B5 · B7 · B8 · B11）
> —— 口径：`design/gdd/systems-index.md` 的 `Depends On` 列含 `A6` 的行数。
> **设计顺序**: 第 6 位（A 系列的最后一个）

---

## Summary

把 A3 算出的"**实际发生了什么**"聚合成一张**以氧计价**的代价面，
并让那 5 个旋钮**可见、可理解、可调** —— **但不定义它们**（定义在 A1）。

## Overview

**⚠️ 先写清它的形状 —— 它由图外的一条已批准处置决定：**

> **A3 ↔ A6 是本项目唯一一处已批准的循环依赖。**
> 原始张力：A6 要展示代价面就得调用 A3 求值；而 A3 用到的参数又由 A6 定义 —— 互为输入。
> **处置（契约拆分）**：把「**有哪些旋钮、各自范围与单位**」这份 schema **下放到 A1 的数据底座**，
> **A6 只剩「表达代价面 + 让参数可见」** → 于是 **A6 → A3 变成单向，循环解开**。

**因此 A6 是表达层，不是计算层**：A3 算出事实，**A6 把这些事实变成"你为此付出了什么"。**

### 三条承重约束（都不是本系统的自由）

**① 无货币 ⇒ 一切代价必须以物质与能量计价。**

> 概念文档 Core Mechanics #6 原文：**「本作没有金币、没有市场、没有售价」**，
> 且特别注明：**「这条不是"少做一个系统"，而是一条会管住所有其它系统的硬约束」**。

→ **A6 正是"代价"住的地方，所以这条在这里落地**：代价的单位**只能是物质与能量**，
而其中**氧是核心计价物**（它同时是生命维持与助燃物 —— **同一个数字**）。
**任何需要一个"卖掉换钱"的出口的设计，在 A6 这里就是错的。**

**② 代价【不是线性的】**（A3 给 A6 的契约里明令：不得假设代价是线性的）。
→ 旋钮偏离最优带时，代价的上升**不是一条直线** —— **而这正是"找平衡点而非最大值"这个核心玩法的来源。**

**③ 参数【不是"生效 / 不生效"两态】**（同样来自 A3 的契约）。
→ 参数是**三段区间**（A2 已定：最优带 / 偏移带 / 越界），**而每一段的代价形状不同**。

### 边界（它不是什么）

- **不定义旋钮** —— schema 在 **A1**（这是解开循环的前提，不能反过来）。
- **不计算代价** —— 事实由 **A3** 算；A6 只**聚合与表达**。
- **不是热力图** —— 数据怎么画属 **B12**。
- **不是 HUD** —— 读数的排布属 **B11**。
- **不是百科** —— 怎么解释给小白听属 **B7**。

**代价面给玩家的是"一片区域（含当前点）"**（已定，见 §Core Rules ④），
**但不是 5 维的全维视图** —— A6 提供**切片**（默认单旋钮切片，见澄清 F-A6-1）。

**A6 不改模拟**（已定，见 ⑤）：A3 算事实，A6 聚合，B7/B8/B11 消费。
**因此它的更新代价只与"要看多少个点"有关**，与模拟规模无关 —— 这是它唯一的性能形状。

**它的错误表现为"误导"，而不是"数值错"**：A3 算得对不对，玩家是从 A6 的表达里判断的。
所以本系统最要紧的不是算得准，而是**表达得不走样**。
它是否要参与任何【计算】（还是纯展示）—— 这决定它是否属于"必须每 tick 更新"的东西]`

## Player Fantasy
**这一层要给的感受**：**「我改一个旋钮，能看见代价。」**

玩家不应靠盲调来找平衡点 —— **他要能看见"往这边偏，代价怎么涨"。**
这是 P2「严谨是美感」在**决策层面**的兑现：**不是算得快，而是代价可预见。**

**反例**：玩家调参数只能靠"试一下、看结果、再试一下" ——
那会把"**找平衡点而非最大值**"这个核心玩法退化成一件事：**穷举**。

## Detailed Design

### Core Rules
| # | 规则 | 状态 | 依据 |
|---|------|------|------|
| ① | **A6 只表达，不定义**：旋钮的名称 / 范围 / 单位 / 默认值**一律引用 A1**（登记册的 `param_*`）。 | ✅ 已定 | 循环依赖的**契约拆分**（见 §Overview）—— **这是解开循环的前提，不能反过来** |
| ② | **代价的单位 = 物质与能量**（**无货币**）；**核心计价物是氧** —— 它同时是生命维持与助燃物，**是同一个数字**。 | ✅ 已定 | 概念文档 Core Mechanics #6 + #5 |
| ③ | **代价的构成项 = 能耗 · 纯度 · 耗时**（三项）。 | ✅ 已定 | **概念文档已给的原话**（见下方澄清） |
| ④ | **代价面呈现"一片区域（含当前点）"**，不只是当前值 —— 玩家必须能看见**往哪边调更省**。 | ✅ 已定 | 用户拍板；服务"**找平衡点而非最大值**"这个核心玩法 |
| ⑤ | **A6 不改模拟，但向其它系统提供数据**（B7 / B8 / B11 消费它）。 | ✅ 已定 | 用户拍板 —— 保持"**A3 是唯一让事实发生的地方**" |
| ⑥ | **代价必须能表达非线性**，且**三段（最优 / 偏移 / 越界）各有不同的代价形状**。 | ✅ 已定 | A3 给 A6 的契约（不得假设代价线性；不得假设参数是对/错两态） |
| ⑦ | **代价必须可归因**：任一参数点上的代价必须能**分解到具体项**（能耗 / 纯度 / 耗时各占多少）。 | ✅ 已定 | B7/B11 的前提 + P2（可推演） |

### 澄清：③ 的代价构成项**不是本系统新定的**

概念文档在讲 **P1 的设计测试**时已经写明：

> 「争'百科直接给这个产物的最优参数' vs '**百科给一条可行解，并让玩家看见它的代价（能耗 / 纯度 / 耗时）**' → **选后者**」

**所以"代价 = 能耗 · 纯度 · 耗时"是你早先定下的结论**，A6 只是把它实现出来。
**把它记在这里，是为了不让后来者以为它是 A6 自己发明的三项** —— 那会在以后某次"优化代价面"时被随意改动。

### ④ 的一个直接推论

**既然要给"一片区域"，A6 就必须能算"邻近参数点的代价"**，而不只是当前点 ——
**这不是界面问题，是数据问题**：它要求 A6 的代价表达是**可采样/可插值的**，
否则 B11 拿不到"往那边偏会怎样"。

（**但它仍不改变模拟**（⑤）：采样的是 A3 已经能算的事实，A6 只是把它们组织成一片形状。）

### 澄清（§5a 自检）：两条结构性问题

**F-A6-1 · "一片区域"在 5 个旋钮上是 5 维 —— 必须给出降维方式**

**5 个旋钮的一片区域 = 5 维空间里的一块，它没法直接呈现。**
所以 A6 **必须定义切片方式**，否则 B11 拿到的是一个无法可视化的东西：

| 切片 | 说明 | 用在哪 |
|------|------|--------|
| **单旋钮切片**（**默认**） | 固定其余 4 个，只变 1 个 → 一条曲线 | 玩家的**实际操作就是逐个调旋钮**，故这是默认视角 |
| 两旋钮等高图 | 固定其余 3 个，变 2 个 → 等高线 / 热力图 | 需要"两个旋钮一起调"的视角时 |
| 全维视图 | **不提供** | 5 维无法呈现；强行降到 2 维会**丢掉玩家正在调的那一维** |

> **默认必须是单旋钮切片**，理由是操作性的：**玩家一次调一个旋钮** ——
> 界面要对齐的是"**这一个旋钮往左/往右，代价怎么变**"，而不是"整个空间长什么样"。

**F-A6-2 · 代价的三项不是同一种东西**

规则 ③ 说"能耗 · 纯度 · 耗时"，但把三者并列成"代价"会误导设计：

| 项 | 性质 |
|----|------|
| **能耗** | **付出**（花掉氧） |
| **耗时** | **付出**（花掉时间） |
| **纯度** | **所得**（换来什么） |

**所以它其实是一个「2 项付出 + 1 项所得」的权衡三角，不是一个三项清单。**

**这条推论直接决定界面组织方式**：**不该"列三个数"，而应显示一个取舍** ——
玩家要看到的是"**我多花能耗，能换到多少纯度**"，而不是三个孤立的读数。


### States and Transitions
**主判断：不适用**（同 A2 的 §States —— **明确写出，不留空**）。

**理由**：按规则 ⑤，A6 **不改模拟**，它聚合上游事实并向外提供数据 ——
**它自身没有运行时状态**（不存在"这张代价面正在变化"）。

**唯一可能的状态是"当前选中的参数点"** —— 但那更像**编辑/查看的上下文**，
**倾向归 B1（编辑）或 B11（HUD）**，而非 A6。`[待确认 —— 见 Open Questions]`

> **注意区分**：A2 那次写"不适用"是因为它是**只读数据**；
> A6 写"不适用"是因为它是**无状态的表达层**。**两者理由不同，都要说清** ——
> 否则后来者会以为"不适用"是个可以随便贴的标签。

### Interactions with Other Systems
**上游 1 个**：A3（实际发生了什么）。
**下游 5 个**（口径：`systems-index` 的 `Depends On` 列含 `A6` 的行数 = **5**）：

| 下游 | A6 承诺给它 | **它不得假设** |
|------|-------------|----------------|
| **B2** 污染物与失败通道 | 各参数点上的**代价与污染形状** | 不得假设**污染与代价是同一件事** —— 污染花在**纯度**上，代价花在**氧与时间**上（见 F-A6-2） |
| **B5** 灾难与失控 | 越界段的**代价陡升形状** | 不得假设**灾难是代价的极端值**（它是**独立的通道**，不是"最贵"） |
| **B7** 百科 | 参数与代价的**可读表达**（含单旋钮切片） | 不得假设**百科能自己算代价**（那是 A3 + A6 的活） |
| **B8** 渐进解锁 | 哪些参数 / 代价概念**何时可见** | 不得假设**参数一出现就附带全部代价信息**；也不得假设**不可见 = 不生效**（解锁只是"看见"） |
| **B11** HUD / UI | 代价面的**当前读数 + 单旋钮切片** | 不得假设**A6 会给出全维视图**（F-A6-1：只提供切片）；不得假设**读数可事后重建** |

✅ 口径与写法纪律同 A1–A5：**「不得假设」那一列比「承诺」那一列更重要。**

## Formulas
> **本节原则（同 A3–A5）**：A6 的公式大多是**聚合上游事实**，不是新发明物理。

### ① 代价的聚合式

```
代价(参数点 p) = { 能耗(p), 耗时(p), 纯度(p) }
```
**三项的性质不同**（见澄清 F-A6-2）：**能耗与耗时是付出，纯度是所得** ——
所以它**不是一个可加和的标量**，而是**一个权衡三角**。
**不得把它们加权成一个"总代价分数"** —— 那会把权衡压平，玩家就看不到取舍了。

### ② 单旋钮切片（默认视角）

```
切片(p, 旋钮 k) = { 代价(p 但把 k 从 lo 扫到 hi) }    其余 4 个旋钮固定为 p 的值
```

### ③ 三段的形状（各自不同）

| 段 | 代价形状 | 说明 |
|----|----------|------|
| **最优带内** | 平缓（代价近似最低） | —— |
| **偏移带内** | **上升且非线性**（这是"找平衡点"的玩法所在） | 具体形式 `[待定]` |
| **越界** | **陡升**（但不是"无穷" —— 它与灾难是两条独立通道，见 B5 的契约） | —— |

### ④ "多花能耗能换到多少纯度"（权衡的量化）

`[待定 —— 这是 F-A6-2 那个推论的可算形式：需要能把两个付出换算成一个所得的变化率]`

## Edge Cases

| 边界 | 行为 | 依据 |
|------|------|------|
| **代价为 0 的参数点** | 允许（例如不耗能的步骤）；**不得当成"没数据"** | ① |
| **越界段代价陡升** | 陡升但**有限**；**不得表达成"无穷"**（那会与灾难混淆） | ③ / B5 的契约 |
| **多个代价项互相抵消** | **允许**（省能耗换耗时的取舍正是玩法）—— **不得自动"优化掉"它** | 澄清 F-A6-2 |
| **参数点落在两段之间** | 用 A2 的 `[a, b)` 约定定归属 | A2 的 `CONDITION_BAND_CONVENTION` |
| **玩家在代价不可见时调参**（B8 解锁前） | **允许**；但**不可见期的代价仍照算** —— **解锁只是"看见"，不是"生效"** | ⑤ + B8 的契约 |
| **两个旋钮同时偏离** | 代价应**同时反映两者**（不是只显示最差的那个） | 对齐 A2 的"各旋钮独立贡献" |

## Dependencies

**上游 1 个**：A3。
**下游 5 个**：见 §Interactions（**本处不重复** —— 同 A1–A5 的纪律）。

### 两条由定位推出的性质

1. **它是唯一一个"结论来自别处、但玩家只看到它"的系统** ——
   A3 算得对不对，玩家无从直接查看，**他只能从 A6 的表达里判断**。
   → 所以 A6 的错误**不会表现为"数值错"，而会表现为"玩家被误导"** —— 那更难发现，也更贵。
2. **它是唯一一个"必须降维才能工作"的系统** —— 5 个旋钮的代价面是 5 维的，
   而**玩家只能看二维**（F-A6-1）。→ **它的核心设计工作不是算，而是"选哪个切面"。**

## Acceptance Criteria
**七条，每条都可独立检验。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **无货币测试**（核心） | 代价面里**不得出现任何货币量** —— 只有物质与能量（Core Mechanics #6 的硬约束） |
| **2** | **非线性测试** | 偏移带内的代价**必须能表达为非线性** —— **用一条直线近似即为失败** |
| **3** | **三段区分测试** | 最优 / 偏移 / 越界三段的代价形状**必须可区分**（不能三段同形） |
| **4** | **不重定义测试** | A6 中出现的旋钮名称 / 范围 / 单位 / 默认值**必须与登记册 `param_*` 逐字段一致** |
| **5** | **降维可用性测试（F-A6-1）** | 单旋钮切片必须能对**任意一个旋钮**生成曲线（固定其余 4 个）；**若只能给全维数据即为失败** |
| **6** | **权衡三角测试（F-A6-2）** | 代价表达必须能回答"**多花能耗能换到多少纯度**"（三项之间可比），**而不是三个孤立读数** |
| **7** | **不改模拟测试（⑤）** | 关闭 / 不查看 A6 时，**模拟结果必须完全不变** —— 证明它确实不参与判定 |

> **第 1 条是硬约束的可测形式**：概念文档说"这条会管住所有其它系统" ——
> **A6 是它的第一道闸**，因为"代价"住在这里。

## Visual/Audio Requirements
**A6 是表达层，本身无视听需求 —— 但它是"代价要被看见"这件事的定义者。**

它必须让下游能表现这些（**具体画法属 B11/B12**）：
- **单旋钮切片曲线**（默认视角）
- **三段的形状差异**（最优平缓 / 偏移非线性 / 越界陡升）
- **权衡的取舍**（不是三个孤立读数，而是"多花能耗换多少纯度"）

> 沿用 `art-bible` §3④ 的纪律：**形状优先于颜色**（饱和度预算只给了氧气与危险）。
> **⚠️ 特别提醒**：代价面天然想用"红黄绿"来表达好坏 —— 而那**恰好是被禁止的那条路**
> （饱和度只给氧气与危险）。**所以代价的图形必须靠形状/位置表达，不能靠色相。**

## Game Feel
**这是 A 系列里最接近"手感"的系统** —— 比 A5 更近一步：**A5 管"动"，A6 管"代价可预见"。**

**它直接决定"调参"这个核心动作的手感**：
- **调完能不能立刻看出代价变化** —— 否则调参没有反馈；
- **能不能看出往哪边调更省** —— 否则调参退化成穷举；
- **能不能看出取舍**（多花能耗换纯度）—— 否则玩家只会找"最便宜的点"，而不是"最适合的点"。

**反例**：调完旋钮，界面只变了几个数字，玩家得自己心算哪个更划算。
**那不是"有深度"，那是"没给出信息"。**

**边界**：具体表现属 B11 —— **A6 只保证"可预见"这件事在数据上成立。**

## UI Requirements
**A6 不直接产出 UI** —— 它是 **B11（HUD）**与 **B7（百科）**的核心数据源。

它对 UI 的义务（都是本轮定下的）：
- **提供单旋钮切片**（默认视角）—— 不能只给全维数据（F-A6-1）；
- **提供可比较的权衡表达** —— 不能只给三个孤立读数（F-A6-2）；
- **提供三段归属**（当前点落在哪一段），供 UI 解释"为什么贵"。

> **一条与 A1/A3/A5 一致的取向**：**给可核对的细节，而不是给一个结论。**
> 例如不要只说「这个参数点很贵」，而要能回答「**贵在能耗还是耗时，往哪边调会更省**」。
