## Summary

**决定"哪些东西什么时候可用"** —— 而它的解锁条件不是等级或时间，**是玩家此刻问出的那个问题**。

## Overview

### 它的立场已经定了两次（**操作**一次、**旋钮**一次）

**第一次（操作）**：概念文档 line 49 ——
> **「教程只教 6 个操作，其余靠参数漂移、百科残页、异常点探测三种游戏内途径发现。」**

**第二次（旋钮）**：**L1 决策（用户已接受）** ——
> **「5 个旋钮不一次给全，按'你什么时候会问这个问题'的顺序解锁。」**

| 解锁时机 | 给的旋钮 | 玩家此刻自己会问的问题 |
|---|---|---|
| **开局** | **温度 T** + **催化剂** | "条件不同，结果真的会不一样吗？" |
| **跑通第一条线** | **压强 P** | "还能更快、或更干净一点吗？" |
| **撞上瓶颈**（产量或纯度） | **停留时间 τ** | "是我反应时间不够吗？" |
| **第一次碰见氯污染**之后 | **阳极材料** | "**氯是从哪来的？我怎么挡住它？**" |

> **概念文档对这条的总结**：**「旋钮在玩家产生疑问的那一刻才出现，
> 而不是开局就摆出五个滑杆。」**

### 🎯 由此得到 B8 的核心性质（这是本系统全部的设计）

**解锁条件是【玩家的处境】，不是【一个数字】。**
- 它**不是**"到 3 级解锁压强"；
- 它**是**"**你跑通了第一条线之后**，压强才出现"。

**→ 所以 B8 不产出"等级"，它产出【触发条件】。**

### 三条约束（全部来自上游契约）

**① 解锁 = 【看见 / 可调】，不是【生效】**（A6 给 B8 的契约，原话）：
> **「不得假设不可见 = 不生效（解锁只是"看见"）。」**
> → 未解锁的旋钮**仍然按默认值在工作**，玩家只是看不到、调不了。

**② 三样东西各有一套阶梯，且都由 B8 统一编排**：
- **操作**（6 个原语）· **旋钮**（5 个）· **连线决策**（4 种，B1 给 B8 的契约：**①最有趣、④最晚**）· **百科条目**（B7 给 B8 的契约：分层）。

**③ 百科的分层也必须由 B8 对齐**（B7 的契约）：
> **不得假设百科一开局就是全的** —— 而它的"起跑线条目"与 B8 的"开局旋钮"**必须同一套边界**。

### 边界（它不是什么）

- **不是知识** —— 那是 **B7**（B7 管"你知道吗"，B8 管"你能用吗"）。
- **不是教程** —— 那是 **B17**（B8 决定"什么时候可用"，B17 决定"怎么教"）。
- **不是参数的物理** —— 那是 **A1/A6**（B8 只决定**看不看得见**）。
- **不是难度曲线** —— 概念文档明写"难度不来自敌人，来自严谨度"，**B8 不是难度系统**。

**解锁的判定机制**：✅ 已定 —— **两条路**（撞上它 / 去查它，③）。

**顺序是否固定**：✅ 已定 —— **主线固定、事件型可提前**（④）。

**能否跳过**：✅ **已被 ③ 解决** —— "去查它"就是跳过（老玩家去百科查一下就行），
所以不需要另做一个"跳过解锁"的功能。

**⚠️ 而 F-B8-1 给了一条新义务**：B8 必须给出未解锁旋钮的**默认值**，
且**它们就是 B7 算起跑线解时用的值**（见澄清 3）。

## Player Fantasy
**方向：**「**我刚好需要它的时候，它就出现了。**」

B8 想要的感受**不是"我在变强"**（那是等级制），而是**"游戏懂我在问什么"** ——
它把认知负荷控制在**你刚好能承受的那一刻**。

**反例**：开局摆出 5 个滑杆。**那玩家会先被吓到，然后在不知道自己在调什么的情况下乱调** ——
而 **P2 的全部价值在于"你理解了你调的是什么"**。

**第二条可能的反例（更要小心）**：**旋钮出现得比疑问晚**。
那玩家会**卡在一个没有工具的问题上** —— 而那比"一次给太多"更伤（前者是负担，后者是挫败）。
**④ 的"事件型可提前"正是为了防这一条。**

## Detailed Design

### Core Rules
| # | 规则 | 状态 | 依据 |
|---|------|------|------|
| ① | **5 个旋钮按 L1 的四个时机解锁**（开局 T+催化剂 → 跑通第一条线 P → 撞上瓶颈 τ → 第一次氯污染 阳极材料）。 | ✅ 已定 | L1（用户已接受） |
| ② | **解锁条件是【玩家的处境】，不是等级或时间。** | ✅ 已定 | 概念文档的总结 |
| ③ | **两条触发路径**：**撞上它**（处境信号，自动出现）+ **去查它**（在百科里查到那条 = 把问题问出口）。 | ✅ 已定 | 用户拍板（见澄清 1） |
| ④ | **主线固定，事件型可提前**：**进程型**（跑通第一条线 / 撞上瓶颈）按顺序；**事件型**（第一次碰见氯污染）**可提前**。 | ✅ 已定 | 用户拍板（见澄清 2） |
| ⑤ | **解锁 = 看见 + 可调**；**未解锁的旋钮仍按默认值生效** —— **"解锁只是看见"**。 | ✅ 已定 | A6 的契约 |
| ⑥ | **6 个操作原语同样走渐进**；且**连线决策的阶梯**（①最有趣、④最晚）由 B8 编排。 | ✅ 已定 | line 49 + B1 的契约 |
| ⑦ | **百科条目的分层必须与 B8 的旋钮边界对齐**（同一套边界）。 | ✅ 已定 | B7 的契约 |

### 澄清 1：为什么"去查它"这条路**必要** —— 而它让 B7 与 B8 咬上

概念文档说「旋钮在玩家**产生疑问**的那一刻才出现」。**而"产生疑问"有两种发生方式**：

| 方式 | 例子 | 谁来提供信号 |
|------|------|--------------|
| **撞上它** | 你第一次被氯污染砸到 | **处境信号**（B2 知道污染发生了） |
| **去查它** | 你自己想到"氯是从哪来的？"然后去查 | **B7 的界面** |

> ### 所以：**在百科里查到"氯从哪来"的那一条 = 你已经把那个问题问出口了 → 阳极材料随之出现。**
>
> **这条让 B7 与 B8 咬上了**：**百科不只是知识库，它同时是"主动解锁"的入口。**
> 而这顺带解决了"老玩家 / 二周目想提前拿旋钮"的问题 —— **他去查一下就行。**

### 澄清 2：L1 那张表**自己就编码了**"主线固定、事件型可提前"

| L1 里的时机 | 类型 | 为什么 |
|-------------|------|--------|
| 跑通第一条线 | **进程型** | 它是"**你走到哪了**" |
| 撞上瓶颈（产量或纯度） | **进程型** | 同上 |
| **第一次碰见氯污染** | **事件型** | **它随时可能发生，与进度无关** |

> **→ ④ 不是我们另加的设计，而是那张表自己编码的。**
>
> **而若不这样**：一个**提前**碰见氯污染的玩家会**面对一个无法回答的问题**
> （"氯是从哪来的？"—— 却没有任何旋钮可以回答它）——
> **那直接违背 ②（旋钮该在疑问出现时出现）。**

### 澄清 3（F-B8-1）：百科的"起跑线解"必须按【未解锁旋钮的默认值】算出来

⑤ 说"未解锁的旋钮仍按默认值生效"。**它有一个不显然的后果**：

> **玩家照百科做第一条线时，那几个旋钮是不可见的、但【在生效】。**
> 所以**百科给的那条可行解，必须是在这些默认值下算出来的** ——
> 否则玩家照做会得到**不一样的结果**，而他会得出一个错误的结论：
> **「百科不准」**（而真相是"你看不见的那个旋钮也在起作用"）。

**→ 推论：B7 的起跑线解与 B8 的默认值必须对齐。**

| 谁 | 必须做什么 |
|----|------------|
| **B8** | 给出未解锁旋钮的**默认值**，且**它们就是 B7 算解时用的值** |
| **B7** | 起跑线解**在这些默认值下成立**（否则"起跑线测试"会失败） |

> **⚠️ 这是"不可见但生效"最不显然的一个后果** ——
> 它不影响模拟（模拟一直是对的），**它影响【玩家对百科的信任】**。
> 而"不能是暗算"这条纪律在这里的形态就是：**玩家照做，就该得到说的那个结果。**


### States and Transitions
每个"可解锁物"（旋钮 / 操作 / 连线决策 / 百科条目）有**两态**：

| 状态 | 含义 |
|------|------|
| **未解锁** | **不可见、不可调** —— 但**按默认值生效**（⑤）；**百科的起跑线解按这些默认值算**（F-B8-1） |
| **已解锁** | **可见、可调** |

**⚠️ 触发来自玩家的处境**，而 B8 **不自己判定处境** —— 它**监听**别的系统的信号：

| 触发 | 信号来自 |
|------|----------|
| 跑通第一条线 | **A5**（图是否稳定运行） |
| 撞上瓶颈（产量或纯度） | **A3**（产量）+ **B3**（纯度） |
| 第一次碰见氯污染 | **B2**（污染发生） |
| 去查它 | **B7**（百科被查到） |

> **→ B8 是【监听者】，不是【判定者】。** 这一条必须写清，
> 否则 B8 会被实现成一个自己判断"玩家是不是撞上瓶颈了"的系统 —— 而它手里没有那些数据。

## Formulas
**B8 没有数值公式** —— 但它是本项目里**第一个以【触发条件】为核心内容的系统**。

```
解锁(物)  <=>  处境信号 ∨ 百科查询          ← 两条路（③）
触发类型：进程型（按顺序） / 事件型（可提前）  ← ④
```

### 一条必须对齐的量（F-B8-1）

```
B7 的起跑线解 必须在 【B8 未解锁旋钮的默认值】 下成立
```
> **若两者不一致**，玩家照百科做会得到不同结果，**而他会以为"百科不准"**。

## Edge Cases
| 边界 | 行为 | 依据 |
|------|------|------|
| **玩家在教程之前就触发了某条解锁** | **允许** —— 触发即解锁（④ 的事件型就是这样设计的） | ④ |
| **多个解锁同时触发** | **允许，但一次只应回答一个问题** —— 否则就等于"开局摆出五个滑杆"（只是晚了几分钟） | ② 的意图 |
| **存档把"处境历史"丢了** | **不允许** —— 解锁状态**不可重算**（B16 的契约），必须存 | B16 的契约 |
| **玩家想主动提前拿旋钮** | **允许** —— **去百科查**（③ 的第二条路） | ③ |
| **解锁了但玩家没注意到** | **需要提示，但不得打断**（本作无时限、连续流） | ⑤ + P5 |
| **玩家不想用新旋钮** | **允许** —— 它就停在那里（**不强制使用**） | ⑤ |
| **未解锁旋钮的默认值被改了** | ⚠️ **会改变百科的起跑线解** → **两者必须一起改** | **F-B8-1** |

### 两条由定位推出的性质

1. **它是唯一一个"以玩家的心理状态为输入"的系统。**
   别的系统的输入都是物质、能量、时间 —— **而 B8 的输入是"玩家此刻在问什么"。**
   → 这决定了它的实现形态：**它是监听者**（等信号），不是判定者（自己算处境）。
2. **它是 B7 的"另一半"，而且 ③ 让两者真正咬合。**
   - **B7 管"你知道吗"，B8 管"你能用吗"**（B7 的澄清 3）；
   - 而 **③ 的"去查它"把 B7 变成了 B8 的一个【主动触发入口】** ——
     **在百科里查到一条 = 把那个问题问出口了。**
   → **两个系统不是上下游，而是同一个"渐进"的两面。**

## Acceptance Criteria

**六条，第 3 条是本轮新增的（F-B8-1）。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **处境触发测试** | 解锁**不得**由时间或等级触发 —— 只能是玩家的处境（或查询） |
| **2** | **仅可见测试** | 未解锁的旋钮**必须仍在按默认值工作**（"解锁只是看见"） |
| **3** | **对齐测试（F-B8-1）** | **百科的起跑线解必须在"未解锁旋钮的默认值"下成立** —— 否则玩家照做会得到不同结果 |
| **4** | **不打断测试** | 解锁**不得打断**玩家正在做的事（它是"出现"，不是"弹出暂停"） |
| **5** | **历史不可重算测试** | 解锁状态依赖处境**历史** → **存档必须存它**，不得靠重算 |
| **6** | **一次一问题测试** | 多个解锁同时触发时，**不得一次涌来** —— 否则它就是迟到的"五个滑杆" |
