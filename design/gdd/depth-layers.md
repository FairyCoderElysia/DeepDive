## Summary

定义**深度是什么** —— 而它的答案不是"生物群系"，是**压强与带宽的连续函数**。
并承担**"强制下潜"这个支柱的实现**：**海水无限但低通量；矿脉高密度但高代价。**

## Overview

### 核心定义（概念文档原文）

> **「深度不是"生物群系"，是【压强与带宽的连续函数】。」**（对《泰拉瑞亚》那条的借镜）

**而它在本作里承担一件事**（概念文档 Design test）：

> 争「让玩家靠海水无限放大产能」 vs 「**让大规模产能必须下潜**」 → **选下潜**。

### 深度的四条权衡（Core Mechanics #4 原文）

> **「越深越赚（矿只在深处），但【带宽越低、管壁越脆、耗氧越高】。」**

| 随深度 | 变化 | 归谁定义 |
|--------|------|----------|
| **矿脉** | 越深越好（**唯一的大宗矿源**） | **C1**（分布）+ C2（开采） |
| **带宽** | **越低** | **C1** |
| **管壁** | **越脆** | **C1**（B5 明确把"管壁脆"推给 C1） |
| **耗氧** | **越高** | **趋势归 B4，具体关系属 C1** |

### 🎯 两条来源分层（这是"必须下潜"的实现）

**① 元素按来源分层**（概念文档 line 291）：
> **「海水能给的元素只是【起步集】；存在【仅矿脉可得】的元素。
> 缺了它们，一部分产物在结构上就做不出来。」**

**② 海水无限但低通量；矿脉高密度但高代价**（line 292）：
> **「所以深度不只是地理阶梯，更是【通量阶梯】：
> 靠海水永远无法把产能放大到后期规模。」**

### ⚠️ 一条 T1 的硬义务（**这条让 C1 早于它的 T3 名义**）

概念文档 Risk #8（line 424）原话：
> **「『深海是必须项』在 MVP 里完全不成立** —— MVP 刻意只在最浅层…
> → 计划：**从 T1 垂直切片起就必须把『表层通量天花板』做出来**
> （让玩家真的感到海水不够用），**否则『必须下潜』在体感上不存在，P4 会退化成一句设定**。」

**→ 所以 C1 虽然是 T3 名义，但它的【表层通量天花板】是 T1 的义务。**

### 一条必须写清的拆分（**否则会重复一次已经犯过的错**）

> 概念文档 **2026-10-02 的拆分**：
> **「『压强』在本作里是两个不同的东西，不能混」** ——
> **(A) 压强作为一个工艺参数 P**：反应器里的旋钮，**MVP 就有**（属 A1/A6 的参数表）；
> **(B) 深度带来的压强**：环境量，**T3**。
> **「本文件先前把这两件事混为一谈…现已分开。」**
>
> **→ C1 只管 (B)。** 而 **(A) 不属 C1** —— 这一条必须写在边界里，
> 因为**概念文档自己在这上面犯过一次错**。

### 边界（它不是什么）

- **不是工艺参数"压强 P"** —— 那是 (A)，属 A1/A6（见上）。**C1 只管环境压强。**
- **不是矿脉本身** —— 那是 **C2**（C1 定义**分布**，C2 定义**开采**）。
- **不是程序生成** —— 那是 **C4**（C1 给"分层与函数"，C4 给"生成"）。
- **不是深度可读性的视觉** —— 那是 **B14**。
- **不是耗氧的具体公式** —— 趋势归 B4，**关系属 C1**（见上表）。

**4 段命名分层与连续函数的关系**：✅ 已定 —— **函数连续、命名分 4 段**（澄清 3）。

**管壁脆的表现**：✅ 已定 —— **降额 + 超限必破（确定性）**（⑥，澄清 1）。

**带宽降低的是什么量**：✅ 已定 —— **带宽与速度是两个量，两者都降**（⑦，澄清 2）。

**深度是什么**：✅ 已定 —— **一条一维轴**（澄清 4，F-C1-1）。

## Player Fantasy
**方向：**概念文档已定：**「深度是可见的压力」** ——
> **「越深，画面越暗、越窄，色偏与噪点越重 —— 玩家不看数字就知道自己下去了」**
> 争"给深层加一层漂亮的生物群系贴图" vs "**让画面本身表达压强**" → **选后者**。

**它的目标是"不看数字就知道自己下去了"** —— 一种**身体性**的感受，而不是读数。

**而它与"必须下潜"的关系是**：**感受说"我在深处了"，机制说"我必须去深处"** ——
两者一个给压力、一个给动力，**合起来才是"深海是必须项"**。
（所以 Risk #8 才说：**没有表层通量天花板，"必须下潜"就退化成一句设定。**）

### 澄清 1：为什么"超限必破"必须是**确定性**的，而不是概率

两条已定的纪律同时排除概率：

| 已定的纪律 | 它要求 |
|------------|--------|
| **B5 ⑨** | **同存档 + 同操作序列 → 灾难必然复现**（P2 的底线："不是运气"） |
| **失败模式表** | **"必须可诊断，不能是暗算"** |

> **所以"脆"的形态是：许用通量随深度下降 + 超过它【必破】。**
> **玩家永远可以算出来**"这段管在这个深度最多能过多少" —— 而那正是"严谨是美感"要的。

### 澄清 2：**带宽 ≠ 速度** —— 而概念文档里用了两个不同的词

| | **带宽** | **速度** |
|---|---|---|
| 它是什么 | **每秒最多过多少物质**（吞吐上限） | **物质跑多快**（延迟） |
| 它影响 | **产能上限** —— 你能造多大 | **响应/反馈** —— 你等多久才看到结果 |

> **Core Mechanics #4 说的是"带宽越低"，而用户的原始确认说的是"深度/压强决定【物流速度】与矿脉分布"**
> —— **两个词指的是两个量，而 ② 把两者都算上了。**
>
> **⚠️ 若不区分**，实现者会把它们**合成一个系数** ——
> 那会让**"通量阶梯"少掉一半**：速度降了只是"慢"，**而只有带宽降才是"造不大"**。

### 澄清 3：**"连续函数"与"4 段命名"不矛盾** —— 而且这是 B14 的硬要求

- 借镜泰拉瑞亚那条：**「深度不是"生物群系"，是压强与带宽的【连续函数】」**；
- Content Volume（line 408）：**「深度分层 4 段（S1→S4）」**。

**两句可以同时为真：函数连续、命名分 4 段** —— 就像泰拉瑞亚的命名分层之下是连续的。

> **而 ⑧ 的"有底"正是让这两个词都成立的原因**：
> **函数是连续的（可无限细分），而底给了它一个可达的终点** ——
> 于是 **S1→S4 是"读到哪"的命名，不是"跳到哪"的台阶。**
>
> **⚠️ 这也是 B14 的硬要求**：它的契约写着"**不得假设深度是离散段（那样画面会跳变）**"。

### 澄清 4（F-C1-1）：**深度是一条【一维轴】，不是一个空间位置**

**本作没有 tile 空间模型** —— Core Mechanics #4 明写：
**「管网是节点 + 边的逻辑图，不是逐 tile 模拟」**（同一件事在 B5 的 F-B5-1 里也已经查明）。

**那"越深""下潜""矿脉只在深处"里的"深度"是什么？**

> ### 它是一条**一维轴**。
> - **节点与边有一个 `depth` 属性**（它们在这条轴上的位置）；
> - **玩家也有一个 `depth`** —— **"下潜"就是沿这条轴移动**；
> - **矿脉属于这条轴上的某些位置。**

**而 2.5D 分层视差（`art-bible` 的资产清单里就有"**分层背景**"）是这条轴的【呈现】，不是它的机制。**

| | 是机制吗 |
|---|---|
| **一维深度轴** | ✅ **是** —— 它是 C1 的全部内容 |
| 分层视差 / 视差滚动 | ❌ **不是** —— 它是 **B14** 对这条轴的画法 |

> **⚠️ 若不写清，实现者会去找一个二维/三维世界模型**，然后发现"逻辑管网"里没有位置可言。
> **这条与 B5 的 F-B5-1 是同一个形状**（那次是"连锁不能走空间"，这次是"深度不是空间位置"）——
> **同一个根源：本作没有空间模型，但机制语言里到处是空间词**（旁边、深处、下潜）。


### States and Transitions
**主判断：C1 是【环境/世界参数】，没有运行时状态**（同 A2/A6 的"不适用"，但要说明它是什么）。

| 它有 | 它没有 |
|------|--------|
| **一条一维深度轴**（澄清 4） | 状态机 |
| 每条边/每个节点的 `depth` 属性 | 迁移 |
| **"哪些层已开通"这个进度**（B16 要存 —— 见 §Interactions） | 运行时变化（深度不随时间变） |

**⚠️ 一条必须确认的实现问题**：设备的 `depth` 是**由它的位置推出**的，还是**被存下来的**？
> **倾向：由位置推出**（否则会出现"设备和它的深度不一致"这种不可能的状态）。
> 而唯一的例外是**已开通的层**（那是玩家的进度，必须存）。

## Formulas
> **本节原则**：C1 的公式是**四条单调函数 + 一条分层表**，它们**必须都能从深度算出**。

### ① 深度 → 带宽（吞吐上限）

```
带宽上限(d) = 单调下降(d)
```

### ② 深度 → 速度（延迟）

```
速度(d) = 单调下降(d)        ← 与①是【两个量】（澄清 2）
```

### ③ 深度 → 管壁许用通量（**超限必破**）

```
许用通量(d) = 单调下降(d)
若 实际通量 > 许用通量(d)  ->  破（【确定性】，不是概率 —— 澄清 1）
```

### ④ 深度 → 耗氧（**B4 消费这个事实**）

```
耗氧(d) = 单调上升(d)        ← 趋势归 B4，关系属 C1
```

### ⑤ 深度 → 元素可得性（**分层，离散**）

```
可得元素(d) = 该深度段的元素集        ← 含【仅矿脉可得】的部分
```

### ⑥ 表层通量天花板（**T1 义务**）

```
海水提取的通量上限（固定）  ->  靠海水永远无法把产能放大到后期规模
```

## Edge Cases
| 边界 | 行为 | 依据 |
|------|------|------|
| **设备跨越两个命名段** | 用它**自己的** `depth`（一条轴上的一个点）；**命名段只是标签** | 澄清 3 + 澄清 4 |
| **命名段边界处显示什么** | **连续值 + 段名** —— **不得跳变** | B14 的契约 |
| **已开通的层能否"关掉"** | 允许，但**没有意义**（那是玩家的进度） | —— |
| **玩家在最深层被切断氧气** | 走 **B4 的三级优先**（不是 C1 的事） | B4 的 ③ |
| **管路超限破裂** | **确定性发生**（澄清 1）—— 且它是**管路失效**，**不是 B5 的灾难**（见下） | ⑥ + 澄清 1 |
| **管路破裂后怎么恢复** | **换管 / 降压** —— 见下方澄清 5 | **验收 7（可复原）** |
| **海水提取的低通量天花板** | **必须真的让人觉得不够用**（**T1 义务**） | ⑤ |
| **矿脉只在高深度** | **C1 定分布、C2 定开采**（C1 不做开采） | ③ |

> **⚠️ 一条必须划清的边界（它与 B5 很像但不同）**：
> **C1 的"管路超限破裂"是【环境超限】导致的机械失效；
> B5 的灾难是【化学反应失控】（失控放热 / 燃烧 / 爆炸）。**
> 两者都会让产线停下、也都可能被**旁通**绕过 —— **但原因链完全不同**，
> 而 **B10 必须能分辨它们**（同 B5 的 §States 里那四种"停"）。

### 澄清 5（2026-10-03 · 跨 GDD 审计查出）：**破裂之后【怎么恢复】** —— C1 原先漏了这条

本条是**跨 GDD 审计的产物**（第 7 处）。查出来的形状很精确：

| 谁 | 说了什么 |
|----|----------|
| **B10**（它的"六种停"表） | 承诺了修法：**「换管 / 降压」** |
| **C1 的 ⑥** | 写了**预防**：管壁脆 = **降额** + **超限必破** |
| **C1 的验收 7** | **承诺了"可复原"**：管路破裂**不得**导致不可恢复 |
| **C1** | ⚠️ **但【没有定义"怎么复原"】** |

> **→ 问题不是"少写一句话"，而是【B10 替 C1 发明了一个修法】** ——
> 而全项目有一条已定的纪律：**B10 是消费者，不是重算者。**
> 所以"换管 / 降压"本该由 C1 定义、B10 引用，而不是反过来。

**修法不发明新机制** —— 它只是把 ⑥ 的"预防"补上它缺的那一对：

```
预防：降额（没破之前，把流量/深度压在许用范围内）
破裂：超限必破（确定性 —— 澄清 1）
修复：① 换管（换成许用通量更高的管）  ② 降压（把流量降回该深度的许用范围内）
```

> **为什么是这两个而不是别的**：它们分别是"改设备"与"改用法"——
> 而**这正是玩家在 C1 面前唯一能动的两件事**（C1 只收**设备与基建**代价，同 C2 的口径）。
> **两条路都要花东西（换管要材料、降压要时间），所以它仍然有代价 —— 与"可复原"不矛盾。**

### 两条由定位推出的性质

1. **它是唯一一个给出"世界形状"的系统。**
   别的系统都在描述**物怎么流**（A1–A6 / B2–B6）或**玩家怎么操作**（B1 / B7 / B8）——
   **只有 C1 描述"这个世界是什么形状"。**
2. **它是唯一一个"机制语言里全是空间词、而模型里没有空间"的系统。**
   "越深"、"下潜"、"矿脉只在深处"、"旁边爆了" —— **这些词全都是空间的**，
   **而本作没有空间模型**（澄清 4 与 B5 的 F-B5-1 是同一个根源）。
   → **所以它的第一义务是：把空间词翻译成【轴上的坐标】。**

## Acceptance Criteria

**七条，第 6 条是本轮新增的（F-C1-1）。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **连续测试** | 深度必须是**连续函数** —— 不得只有 4 个离散档位 |
| **2** | **命名段测试** | 4 段是**命名**（可读性），**不是数值台阶** |

| **4** | **元素分层测试** | 存在**仅矿脉可得**的元素，且没有它**某类产物结构上做不出来** |
| **5** | **两条压强不混测试** | **环境压强 (B) 不得与工艺参数 P (A) 混为一谈**（概念文档犯过一次） |

| **7** | **可复原测试** | 深潜失败 / 管路破裂**不得**导致不可恢复（与全项目纪律一致） |

## Visual/Audio Requirements

**概念文档已定**（line 359）：
> **「深度是可见的压力：越深，画面越暗、越窄，色偏与噪点越重 —— 玩家不看数字就知道自己下去了」**
> 争"给深层加一层漂亮的生物群系贴图" vs "让画面本身表达压强" → **选后者**。

**⚠️ 并且概念文档明确排除等轴测**（line 404）：
> **「2D 侧视 + 分层视差（2.5D 表现）。明确排除等轴测 —— 它会压缩纵轴，直接摧毁『深度』这个机制。」**

→ **C1 的义务是给出"连续的深度值"**（B14 才能把它变成画面信号）。

## Game Feel

`[待定]` —— 方向：概念文档的"画面越暗、越窄、色偏、噪点越重"就是它的手感设计。
**它的目标是"不看数字就知道自己下去了"** —— 一种**身体性**的感受，而不是读数。

## UI Requirements

`[待定]` —— 方向：**它应该是"最不需要 UI"的系统** ——
因为概念文档选了"让画面本身表达压强"，**而不是加一个深度读数面板**。
（但《泰拉瑞亚》那条提到"常驻深度读数"是它验证过的东西 —— 需确认本作要不要。）
沿用全项目取向：**给可核对的细节，而不是给一个结论**。
