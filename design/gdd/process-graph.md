## Summary

把玩家连出来的**节点 + 边**的工艺图，用 **A3 定义的求值语义**跑成**连续流** ——
决定谁先取料、产物往哪流、以及"接不住"时会发生什么。

## Overview

**它在"数据 → 世界"这条线上的位置**：
`A1 元素（数据）` · `A2 化合物与步骤（数据）` → `A3 求解语义` → **`A5 对图求值（连续流）`**。
**A3 说"一个步骤怎么算"，A5 说"整张图怎么同时流动"。**

### 🚨 三条承重约束（都不是本系统的自由，且第一条来自一条明确的警告）

**① 本体是【连续流】，不是批次结算。**

> 概念文档原文（Core Mechanics #4 下的一条警告）：
> **「T0 v1–v4 是"批次"模型……而本作本体是连续流。」**
> **「不要把"每批结算""清洗一次算一批"这类概念写进任何系统 GDD」**
> —— **结垢是连续累积速率，清洗是一段停机时间，不是回合制。**

**这条警告就是给 A5 的**（"连续流"住在这里）。**A5 的任何设计都必须是连续量 + 速率，
而不是"跑一批 → 出结果 → 再跑一批"。** 那条警告还说清了它为什么危险：
**这类"原型的方便"是很容易悄悄变成设计债的。**

**② 管网是【节点 + 边】的逻辑图，不是逐 tile 模拟。**
（同样来自 Core Mechanics #4。）→ 这直接决定了 A5 的性能形状与数据形状。

**③ 产物必须【立刻】被下游或储罐接住。**（Core Mechanics #4：「输入即刻变输出，产物必须立刻被下游或储罐接住。」）
→ **"接不住"时必须有一个明确的行为** —— 这是本系统最需要在 §Core Rules 里定死的一条。

### 边界（它不是什么）

- **不是数据** —— 元素属 A1、化合物与步骤属 A2、**求值语义属 A3**。
- **不是连线编辑** —— 玩家怎么连、四种连线决策属 **B1**（A5 提供"图上有什么"，B1 提供"怎么编辑"）。
- **不是热力图** —— 数据怎么画属 **B12**（A5 暴露状态，B12 负责呈现）。
- **不是性能预算本身** —— **B19 专管"管网 tick 的预算"**，且 **B19 只依赖 A5** → A5 是它的唯一上游。
- **不是深度/带宽** —— 深度分层与通量阶梯属 **C1**（T3）。

**图与边的规模（暂定）**：概念文档的措辞是「**数百管段下的 tick 开销**」→ 典型量级
**100–500 条边 / 50–200 个节点**；**上限交 B19 定**（它只依赖 A5）。

**活跃集的定义**：**本 tick 可能改变状态的节点** —— 有新输入到达 / 上一 tick 未稳定 / 容量变化。
（"每 tick 重算"还是"增量维护"属开放问题。）

**环路**：**允许**（循环工艺是玩法），按规则 ⑥ 迭代到不动点。

**与 B19 的交付物**：A5 给出"**一次求值的工作量形状**"（含那个**嵌套不动点**），
B19 决定"一个 tick 里装得下多少"。
A5 与 B19 之间的交付物形状]`

## Player Fantasy
**这一层要给的感受**：**「我连出来的东西会自己流动。」**

A5 是 P3「连出来的工艺属于玩家」在**动态**层面的兑现：
玩家不是在按一个"运行"按钮，而是在**看着自己搭的系统持续工作**。

**连续流的核心手感是"它一直在动"** —— 而批次模型会把它变成"我点一下、它算一下"，
**那样玩家就不再是在经营一座工厂，而是在做一组实验。**
（这也是概念文档要专门写一句警告的原因：原型的批次模型**不能渗进来**。）

**反例**：玩家改了一根线，却看不出流动立刻变化 —— 那会让人怀疑**图是不是真的接上了**。

## Detailed Design

### Core Rules
| # | 规则 | 状态 | 依据 |
|---|------|------|------|
| ① | **图模型 = 节点 + 边**（逻辑图）。**不得引入逐 tile / 逐格的概念。** | ✅ 已定 | 概念文档 Core Mechanics #4 |
| ② | **求值语义来自 A3** —— A5 **只应用、不重定义**（**不得自定义求值顺序**）。 | ✅ 已定 | A3 的 §Core Rules ① + A3 给 A5 的契约 |
| ③ | **活跃集由 A5 决定**（A3 只求解该集合内的层内联立）。 | ✅ 已定 | A3 的 §Overview |
| ④ | **连续流，不是批次**：所有量都是**连续速率**；累积量（结垢等）是**速率的积分**；清洗是**一段停机时间**，不是"算作一批"。 | ✅ 已定 | **概念文档的明确警告**（见 §Overview ①） |
| ⑤ | **接不住 → 阻塞上游 + 告警**：**下游的缓存/储罐**满时（**不含"下游机器慢"** —— 那是自然反压，见澄清 4），上游停产并告警。**绝不丢弃**（丢弃 = 物质凭空消失）。 | ✅ 已定 | 用户拍板；**与 A1 的"饱和 → 上游阻塞"同一条语义** |
| ⑥ | **环路 → 迭代到不动点**（带迭代上限 + 超限告警）。**注意：它与 A3 的层内不动点不是同一层**（见下）。 | ✅ 已定 | 用户拍板；与 A3 的机制同构 |
| ⑦ | **A5 持有图**（存图 + 求值）；**B1 只是编辑器**（改图、四种连线决策）。 | ✅ 已定 | 用户拍板 —— 依赖方向因此正确（**B1 → A5**） |
| ⑧ | **性能形状**：规模随**管段数**增长；与 A1（原子数）、A3（机器数）**是不同维度**。 | ✅ 已定 | 观察 —— 三者正交，**B19 必须分别预算** |

### ⑤ 与 A1 的一致性（全项目只有一套"无处可去"的语义）

A1 已定：**元素饱和 → 上游阻塞 + 告警，绝不丢弃**。
A5 现在定：**产物接不住 → 上游阻塞 + 告警，绝不丢弃**。

> **这两条必须是同一条语义。** 否则玩家会遇到两种"产不出来"：
> 一种是卡住（可理解），另一种是**东西消失了**（不可理解、且违反 P2）。
> **同一件事在不同系统里有两种行为，是本项目反复踩的那类坑。**

### ⑥ 的两个不动点要分清（防混淆）

| | **A3 的层内不动点** | **A5 的环上不动点** |
|---|---|---|
| 解决什么 | 同一优先级内多机争同一池料时，**份额**怎么分 | 图上的**环**导致某节点的输入依赖它自己的输出 |
| 迭代对象 | 分配份额 | 沿环传播的**流量** |
| 作用层次 | **一个优先级层内** | **整张图上** |
| 上限 | `SOLVER_FIXPOINT_ITERATION_CAP`（8 轮，A3 已定） | A5 自己的上限（`[待定]`） |

> ### ⚠️ 两者会【嵌套】—— 这是 A5 的主要性能风险
>
> 在环上传播时，**每一个被访问到的优先级层，内部仍要解一次 A3 的不动点**。
> 所以最坏情况的工作量 ≈ **环的迭代轮数 × 层数 × 层内迭代轮数**。
> **这不是"两个独立的迭代"，而是嵌套的。**
> **必须交 B19（它只依赖 A5）当第一号预算问题** —— 见 §Interactions 给 B19 的那条契约。

### States and Transitions
**这是第三层状态，与 A1 的"池"、A3 的"机器"必须区分清楚：**

| 层 | 状态载体 | 状态 |
|----|----------|------|
| **A1** | 池（每种元素） | 正常 / 稀疏 / 饱和 / 对账锁 |
| **A3** | 机器（每个步骤） | 空转 / 运行 / 饱和 / 灾难 / 对账锁 |
| **A5** | **节点（图上的每个节点）** | **活跃 / 阻塞 / 干涸 / 满溢** |

| A5 状态 | 含义 | 进入 | 退出 |
|---------|------|------|------|
| **活跃** | 本 tick 参与了求解 | 在活跃集内 | 离开活跃集 |
| **干涸** | 上游没给它东西 | 上游停 / 无输入 | 上游恢复 |
| **阻塞** | **它产不出去**（下游满 + 储罐满） | 规则 ⑤ | 下游腾出容量 |
| **满溢** | 它自己满了（节点自带缓存满） | 缓存触顶 | 下游取走 |

**三层的相互触发（必须写清，否则会互相打架）**：
```
A1 元素饱和      --> A3 机器"饱和"   --> A5 节点"阻塞" --> 上游节点"干涸"
A5 节点"阻塞"    --> 上游 A3 机器停产 --> 上游 A5 节点"干涸"
```
**注意方向**：**"阻塞"是向下游压力反向传播的** —— 一个节点满，会让它上游的所有都停下来。
**这正是玩家会看到的"我的产线卡住了"**，而它必须能被追溯到**最初的那个满点**（B12/B10 的前提）。

## Formulas
> **本节原则（同 A3/A4）**：A5 的公式大多是**调用上游已登记的公式**，不是新发明。

### ① 图求值顺序 —— **不在此重定义**
用 A3 的 `priority_tier_allocation`（层间抢料 + 层内等分 + 不动点）。

### ② 连续流速率的积分

```
累积量(t) = 累积量(t-1) + 速率 × dt          ← 连续的，不是"按批累加"
```
结垢等累积量走此式；**清洗 = 一段停机时间**（期间速率为 0），
**不是"算作一批"**（那是原型模型，概念文档明确禁止渗入）。

### ③ "接不住"的判定式

```
若  本 tick 想推出的量  >  下游可用容量 + 储罐余量
则  规则 ⑤：阻塞上游 + 告警（绝不丢弃）
```
**判定发生在上游节点想推出去的那一刻**，不在边上（见 §Edge Cases 澄清 3）。

### ④ 环路的收敛（**嵌套迭代**）

```
重复：
   沿环传播流量 -> 每个被访问的优先级层内部解一次 A3 的层内不动点
   若所有节点的流量都不再变化 -> 稳定，退出
   否则继续
达到迭代上限仍未稳定 -> 采用当前值 + 告警（不得静默）
```
> ⚠️ **外层是环、内层是 A3 的优先级层 —— 它是嵌套的。**
> **最坏工作量 ≈ 环迭代轮数 × 层数 × 层内迭代轮数** → **B19 的第一号预算问题。**

| 边界 | 行为 | 依据 |

| **产物接不住** | **阻塞上游 + 告警**（绝不丢弃） | ⑤ |

### 澄清 3：**边承载的是"流"，不是物质**

概念文档说「**输入即刻变输出**」→ 所以**物质只存在于节点与储罐里**，
**不存在"管子里还有半管料"这种状态。**

**这一条消掉了一整类问题**：
- **改线 / 拆线是安全的** —— 没有在途物料会被丢弃（否则删一根线就会违反 P2）；
- **"接不住"的判定只发生在一处** —— 上游想推出去的那一刻；
- **存档不必记录"边上的物料"**（B16 的负担随之下降）。

> **若这一条不写明，实现者很自然会做出"边上有缓冲"的模型** ——
> 那会让删线变成物质泄漏，而且是**最难查的一类：只在玩家改线时发生。**

### 澄清 4：**"下游可用容量"指的是【缓存 / 储罐容量】，不是【下游机器的处理速率】**

规则 ⑤ 说"下游满 **且** 储罐满时阻塞上游" —— 这里的"满"必须限定为**缓存与储罐**。
**下游机器本身不构成"接不住"**：

- **一台慢机器会自然反压** —— 它消耗得慢，上游就会跟着慢下来。**那是正常的连续流行为，不是阻塞。**
- **"接不住"只发生在产物【无处可放】时** —— 下游没有缓存余量、且所有储罐都满。

> **两者必须分开，否则玩家看到的"卡住"就无法归因**：
> "因为下游机器慢"（可以调参解决）与"因为储罐满了"（要加罐或改流程）**是两种完全不同的问题**，
> 而它们的修法完全不同。混在一起，"我的产线卡住了"就变成了一句无法行动的话。


## Dependencies

### 两条由定位推出的性质

1. **它是"三层状态"里最外面的一层** —— A1（池）→ A3（机器）→ **A5（节点/图）**，
   而**压力是从外向内反向传播的**（节点阻塞 → 机器停产 → 池不再被消耗）。
   → **调试任何"卡住"的问题，都必须从最外层那个"阻塞"节点开始找**，而不是从池开始。
2. **它是唯一一个"性能风险来自自己的迭代结构"的系统** ——
   A1 的规模来自数据量、A3 来自机器数，而 **A5 的规模来自"嵌套迭代"**（环 × 层 × 层内）。
   → 这使 A5 成为**最可能超预算的系统**，也解释了为什么 B19 只依赖 A5。

## Acceptance Criteria
**八条，每条都可独立检验。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **连续流测试**（核心） | 同一张图连续运行 → 结果必须**随速率连续变化**，**不得出现"按批跳跃"**（承重约束 ① 的可测形式） |
| **2** | **接不住测试** | 构造"产出 > 下游容量 + 储罐余量" → 必须**阻塞上游 + 告警**，**绝不丢弃物质** |
| **3** | **反压 vs 阻塞区分测试** | 把下游换成一台**很慢但缓存充足**的机器 → 上游应**自然减速**（连续流），**不得**被判定为"接不住" |
| **3** | **环路测试** | 含环（含自环）的图**必须能求解且不死循环**；达迭代上限 → 采用当前值 + 告警 |
| **4** | **语义一致性测试** | 同一张图在 A5 上的结果，必须与 **A3 单独求值的语义一致**（A5 不重定义） |
| **5** | **改线安全性测试** | 在任何时刻删/加一条边 → **物质总量不变**（因为边不持有物质） |
| **6** | **阻塞可追溯测试** | 一个节点阻塞时，**必须能追溯到最初那个满点**（B12/B10 的前提） |
| **7** | **规模测试** | 数百管段的图在单 tick 内可解（**与 B19 联测**） |

> **第 1 条是承重约束 ① 的可测形式** —— 它专门用来防"原型的批次模型渗进来"：
> **如果实现退化成"按批结算"，第 1 条会失败**（结果会出现台阶而不是连续变化）。

## Visual/Audio Requirements
**A5 是算法层，无直接视听需求。**

但它是"**流动**"的来源 —— 所以它必须**暴露足以表现流动的状态**：

- **每个节点的当前速率与状态**（活跃 / 阻塞 / 干涸 / 满溢）—— **这四种必须可区分**；
- **阻塞的传播链**（哪个节点先满、压力如何向上传）—— 这是"我的产线卡住了"能被解释的前提；
- **但不需要 A5 决定怎么画** —— 呈现属 **B12**。

> 沿用 `art-bible` §3④ 的纪律：**形状优先于颜色**（饱和度预算只给了氧气与危险）。

## Game Feel
**A5 是最接近"手感"的算法层**，但**它只提供前提，不提供表现**。

**它提供的前提是"动"**：
- **连续流的手感来自"它一直在动"** —— 批次模型会把它变成"我点一下、它算一下"；
- **改线必须立刻反映到流动上** —— 否则玩家会怀疑图有没有真的接上；
- **卡住时必须能看出"卡在哪里"** —— 否则"我的产线不工作了"会变成一句抱怨，而不是一个可解的问题。

**反例**：玩家改了一根线，等了半天看不到变化，也不知道为什么没变化。**那不是难度，那是"看不见"。**

**边界**：具体表现（动画、音效、高亮）属 B12/B16 与表现层 —— **A5 只保证状态存在且实时。**

## UI Requirements
**A5 不直接产出 UI** —— 它是 **B1（编辑）**、**B12（读数）**、**B19（预算）**、**B9（工艺卡）**的数据源。

它对 UI 的唯一义务是：**把图的状态以结构化形式暴露出去**，至少包括：

- **每个节点的状态与速率**（四种状态可区分）
- **阻塞的传播链**（从最初满点到受影响的节点）—— 这一条决定玩家能否**自己定位问题**
- **图的合法性判定结果**（B1 编辑时要即时反馈"这样连行不行"）

> **一条与 A1/A3 一致的取向**：**给可核对的细节，而不是给一个结论。**
> 例如不要只说「图卡住了」，而要能回答「**从哪个节点开始卡的、因为什么满的**」。
