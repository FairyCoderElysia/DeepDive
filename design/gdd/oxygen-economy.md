> **Status**: **Approved**（2026-10-02 评审通过 —— 见 `design/gdd/reviews/oxygen-economy-review-log.md`）

> **被依赖**: **4 个**（B1 · B11 · B12 · C1）

> **设计顺序**: Core 段第 6 项

## Summary

**氧是本作唯一的硬通货** —— 因为它是**唯一同时被生命与工业拉、且不可绕过**的那种物质：**生命维持 + 助燃物**，
**而这两件事是同一个数字**。B4 把 A3 算出的物质与能量事实，记账成**氧的收支**。

> **⚠️ 本系统的核心规则大部分【已经由用户定下】**（概念文档 Core Mechanics #5/#6 及其下的表与推论）。
> **B4 的工作不是发明，而是把这些整理成可实现的 GDD 形式** —— 并保证它不被稀释。

## Overview

**它的定位不是"一个资源系统"，而是"代价的记账单位"。**

任何一件事贵不贵，**最终都要落到氧上**：
- 造东西要耗氧（**助燃物** —— 烧燃料供能要按化学计量配氧）；
- **活着也要耗氧**（生命维持）；
- **存东西持续耗氧**（Core Mechanics #5：储存本身持续耗氧，**不是一次性达标**）；
- **销毁东西也耗氧**（把物质弄没不是免费的）。

### 五条承重约束（全部来自已定的概念文档）

**① 氧是唯一的硬通货（无货币）。**
> Core Mechanics #6：**「本作没有金币、没有市场、没有售价」**，且
> **「任何设计如果需要一个'卖掉换钱'的出口，就是错的」**。

**② 双角色【共用同一个数字】—— 不得拆成两个池。**
> Core Mechanics #5：氧**既是生命维持，又是助燃物**。**同一个数字。**
> → **若把它拆成"生命维持池"与"工业池"两个池，支点就断了。**
> 玩家要面对的正是**同一个数字被两边同时拉**这个张力。**这是本系统第一号不可违反的约束。**

**③ 低纯产物在账上是【负值】，不是折价正值。**
> 概念文档推论 1：**「低纯产物不是'少赚'，而是'要花钱（氧气）去处理'」**。

**④ 存贮与销毁都不是免费的。**
> 推论 2：**存贮 = 占罐容 + 持续耗氧** → **"先攒着以后再说"本身就是一个有代价的决定。**
> 推论 3：**销毁 = 一次性耗氧** → **这让人不得不面对"当初为什么会产出它"**。

**⑤ NOT 绕开氧气（这是一条反支柱）。**
> 概念文档 anti-pillar：**「氧气既是助燃物又是生命维持，是整个张力的支点；一旦存在绕开它的路，支点就断了」**。

### 边界（它不是什么）

- **不是生产氧** —— 氧从哪来由 A3 与机器决定。
- **不是储罐容量** —— 罐容属 **B6**（B4 说"存贮要耗氧"，B6 说"装得下多少"）。
- **不是纯度分级** —— 档位判定属 **B3**（B4 消费档位，不定义档位）。
- **不是代价面的表达** —— 怎么呈现代价属 **A6**（B4 提供"氧的收支"这个事实）。

**收支的形状 = 存量 + 速率（两者都要）**：
- **速率**回答"往里还是往外"；**存量**回答"还能撑多久"。**缺一个都不行** ——
  只有速率看不出剩余时间，只有存量看不出趋势。玩家要用的是**两者一起**。

**与 B6（储罐）的接缝**：**存贮耗氧率是 B4 的规则**（持续耗氧），**罐容上限是 B6 的**。
"存不下时怎么办"不由 B4 定 —— 它落到 **A5 的阻塞语义**（产物接不住 → 阻塞上游 + 告警）。

**生命维持的消耗**：单人玩家 → 基础速率固定；**它是否随深度变化**属开放问题（C1 的接缝）。
生命维持的消耗在什么条件下变化（深度？人数固定=单人？）· 与 B6 罐容的接缝]`

## Player Fantasy
**方向已经写好了 —— 就是那句话：**

> **「氧气既是你的命，也是你的电。」**

它的感受**不是"资源管理"，而是【同一个数字被两边同时拉扯】**：
你想多造一台机器（要氧），但你也想活着（也要氧），**而这两个需求不能分开算账**。

**而它有一条可测的验收**（概念文档 T1 的验收，原话）：

> **≥70% 的玩家能举出至少一次"为了留氧气而放弃某个产出"的具体取舍。举不出来 = 张力不存在。**

**这条是本系统最硬的验收** —— 它不是"玩家喜欢氧经济"，而是**玩家真的为它做过取舍**。
一个玩家如果从来没为氧放弃过任何东西，**那这个系统在体验上就等于不存在。**

**反例**：玩家从头到尾氧都用不完。**那说明耗氧系数太松** —— 而不是"玩家玩得好"。
**张力必须一开始就成立**（概念文档：核心张力必须在第一个可玩版本里就成立）。

### ⚠️ F-B4-1：③ 为什么必须是【三级】优先，而不是"工业全停"

**"工业让位于生命维持"若直译成"工业全停"，会造成死锁：**

```
氧耗尽 --> 所有工业设备停摆 --> 【制氧设备也是工业设备】--> 它也停
       --> 永远无法产氧 --> 氧永远为零 --> 不可恢复
```

**这直接违反全项目的纪律：所有状态都必须可复原**（A1/A3/A5 都写了这一条，理由是 P5 无时限、不能有死档）。

**所以"让位"必须展开成三级优先：**

| 优先级 | 谁 | 说明 |
|--------|----|------|
| **1（最高）** | **生命维持** | 先保证人不死 —— 这是 ③ 的本意 |
| **2** | **产氧链本身** | 只维持"能继续产氧"所需的最小工业 —— **这一级的存在就是为了避免死锁** |
| **3（最低）** | **其他工业** | 氧紧张时被压缩的那部分 |

> **它与 A3 的优先级机制同构**（层间抢料 + 层内联立）——
> **所以这里不需要新机制，只需要"氧紧张时按这三层分配"这条规则。**
> 并且**同一池氧的事实不变**（规则 ② 仍然成立）：三级优先是**分配顺序**，不是三个池。

### ⑤ 的表（**原样来自概念文档**）

| 档位 | 允许的出路 | 代价 |
|------|-----------|------|
| **洁净 / 可用** | **交付**（进入下游或生命维持） | 无额外代价 |
| **需精制** | ① 接分离产线（→ 变回可用）· ② 存贮 · ③ 销毁 | ① 分离耗氧 · ② 占罐容 **+ 持续耗氧** · ③ 一次性耗氧 |
| **不可用（太脏）** | **只剩 存贮 / 销毁**（分离也救不回来） | 同上，且**没有"低价卖掉"这个出口** |

> **注意第 3 行的最后半句** ——「**没有"低价卖掉"这个出口**」是这张表里最重要的一格：
> **它把"无货币"从一句口号变成了一个可检验的缺失。** 玩家在"不可用"档位上**必须面对**存贮与销毁，
> 不能有任何绕开的路径 —— 这就是 P2 的张力所在。

### ④ 的实现边界（**这条写清，否则有人会去改 A1**）

**"游离的 O₂"不需要 A1 或 A3 做任何改动** —— 因为：

> **游离氧就是化合物表里的那个 O₂ 化合物。**
> A1 的池记的是**元素原子数**（含水里那些氧），而 **A2 的化合物表**区分了 O 是以 `H₂O` 还是 `O₂` 存在。
> **→ B4 读的是「A2 表里 `O₂` 这个化合物的存量」，而不是"A1 池里的全部 O 原子"。**

**这也顺带解释了为什么"水里有氧却不能呼吸"能在本作里自然成立** ——
它不是一条特例规则，而是**化合物模型本来就支持的区分**。

### States and Transitions
本系统的状态是**【账目状态】**，不是机器状态（与 A1/A3/A5 的三层状态都不同）：

| 状态 | 含义 | 进入 |
|------|------|------|
| **盈余** | 净收支 > 0 | 产氧 > 耗氧 |
| **平衡** | 净收支 ≈ 0 | —— **这是 ⑧ 那个"第四级难度"追求的状态** |
| **赤字** | 净收支 < 0，但存量还够 | 耗氧 > 产氧 |
| **耗竭** | 存量归零 | → **按规则 ③ 的三级优先分配** |

**迁移**：`盈余 ⇄ 平衡 ⇄ 赤字 → 耗竭 →(靠"产氧链"这一级恢复)→ 赤字 …`

**一条纪律（来自 F-B4-1）**：**"耗竭"必须是一个可离开的状态。**
若它变成"永远回不来"，那就违反全项目"所有状态可复原"的纪律 —— 而 ③ 的三级优先正是为此存在。

## Formulas
> **本节原则（同 A3–A6）**：B4 的公式大多是**记账**，不是新发明物理。

### ① 氧的收支式

```
净收支 = 产氧速率 − (工业耗氧 + 生命维持耗氧 + 存贮耗氧 + 销毁耗氧)

⚠️ **「工业耗氧」的口径（2026-10-03）**：它 = **燃烧燃料所耗的氧，按化学计量配比给出**（燃料是物质）；
   它**不再**表示「能量本身」。浅层的能量由**光**免费供给 ⇒ **浅层这一项为 0**。
存量  += 净收支 × dt                     ← 速率积分（连续流，不是按批结算）
```

### ② 存贮的持续耗氧（推论 2）

```
存贮耗氧率 = f(当前存储量)                ← 【是速率，不是一次性扣费】
```

### ③ 档位 → 代价的映射

```
档位由 B3 给出；B4 给出该档位对应的代价：
    洁净/可用      -> 0（交付无额外代价）
    需精制         -> 分离耗氧 / 存贮(占罐容 + 持续耗氧) / 销毁(一次性耗氧)
    不可用         -> 只有存贮与销毁（【没有"低价卖掉"】）
```

### ④ 越深越贵（与 C1 的接缝）

```
耗氧 随 深度 单调上升                     ← 具体关系属 C1，B4 只消费这个事实
```

### ⑤ 氧紧张时的三级分配（F-B4-1）

```
当 存量 < 阈值:
    按【生命维持 > 产氧链本身 > 其他工业】分配
    —— 它是【分配顺序】，不是三个池（规则 ② 仍成立）
```

## Edge Cases
| 边界 | 行为 | 依据 |
|------|------|------|
| **氧存量为零** | **三级优先分配**（生命维持 > 产氧链 > 其他工业）—— **因此不会死锁** | ③ / F-B4-1 |
| **氧收支为负** | 允许（赤字是状态之一）；但**必须可见**（B11 的收支读数） | §States |
| **同一 tick 内既产氧又耗氧** | 按**净收支**结算；**顺序不影响结果**（与 A3 的"层内联立"一致） | A3 的确定性纪律 |
| **存贮趋满** | 存贮耗氧率上升；**存不下时走 A5 的阻塞语义**（不是 B4 定） | 与 B6/A5 的接缝 |
| **"不可用"档位无处可去** | **只剩存贮 / 销毁**，两者都要氧 —— **这就是设计要的困境** | ⑤ 的表第 3 行 |
| **玩家把含氯物流送回电解池** | 允许 —— **这是那个"诱人的错答案"，必须存在**（污染雪上加霜） | ⑦ |
| **生命维持中断的瞬间** | 不存在"中断" —— 三级优先的第一级永远是生命维持 | ③ |

### 两条由定位推出的性质

1. **它是唯一一个"玩家会为了它改变整条工艺"的系统。**
   A1–A6 提供事实与表达，而 B4 **提供了那个让玩家说"这条线不能这样走"的东西** ——
   **它是 P2「严谨是美感」从"数值"变成"决策"的转折点。**
2. **它的数字必须是【一个】。**
   任何试图把氧拆成"生命维持"与"工业"两份的实现，**都会拆掉支柱** ——
   而三级优先（③）是**在同一个数字上的分配顺序**，不是两个数字。
   **这两件事很容易被实现者混为一谈**（"分成三层"听起来像"分成三个池"），所以必须写清。

## Acceptance Criteria

**六条，每条都可独立检验。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **🔴 张力存在性测试**（概念文档已定） | **≥70% 的玩家能举出至少一次"为了留氧气而放弃某个产出"的具体取舍** —— **举不出来 = 张力不存在** |
| **2** | **单池测试** | **氧只能有一个池** —— 若实现里出现"生命维持氧"与"工业氧"两个数字，即为失败 |
| **3** | **可恢复性测试（F-B4-1）** | 把氧打到零 → **必须仍能靠"产氧链"这一级恢复**；若进入"无法产氧"的永久状态，即为失败 |
| **4** | **负值测试** | 一个"需精制"产物在账上必须显示为**负贡献**（不是折价正值） |
| **5** | **持续性测试** | 存贮的耗氧必须是**速率**（时间不推进则不再增长），**不得是一次性扣费** |
| **6** | **无货币测试** | **任何"卖掉换钱"的出口都必须不存在** —— 尤其"不可用"档位只剩存贮/销毁 |

> **第 1 条与其它系统的验收性质不同**：它不是对代码的验收，**而是对玩家体验的验收**（一个百分比）。
> **这正是"张力必须一开始就成立"这句话的可测形式** —— 它无法靠自检替代，只能靠真实玩家。

## Visual/Audio Requirements
**概念文档已定一条，且它与 `art-bible` 完全一致：**

> **「氧气用唯一固定的青色，且生命维持与助燃物两个角色共用这一个颜色身份」**
> —— 因为它们在机制上**本来就是同一个数字**。

**这与 `art-bible` §1/§4 的「青色只给氧气」是同一条规则** —— 本处**只指路，不复述**（同 A1–A6 的纪律）。

**另需（B4 特有）**：**氧收支为负时必须有可辨识的警示** ——
且**不得只靠颜色**（`art-bible` §3④「形状优先于颜色」；饱和度预算只给了氧气与危险）。

## Game Feel

**方向：让玩家"喘不过气"—— 但要是【预算】的压迫，不是【倒计时】的惊吓。**

氧的双角色意味着玩家会同时感到"想扩张"与"要活着"两种压力，
而本系统的目标是让这个张力**被感到**，而不是被算出来。

> ⚠️ **一条必须守住的边界**：概念文档明确 **无时限、无强制终点**。
> 所以氧的压力应该是「**预算**」（可规划、可解决、可复原），
> **而不是「倒计时」**（只能反应、且最终必然收场）。
> **F-B4-1 的三级优先正是这条边界的机制保障** —— 它保证了"紧绷但不会终结"。

## UI Requirements

**B4 不直接产出 UI** —— 它是 **B11（HUD）**与 **B12（热力图）**的数据源。

它对 UI 的义务：
- **收支的分解**（哪几项在耗：工业 / 生命维持 / 存贮 / 销毁）
- **存量 + 速率两者**（存量答"还能撑多久"，速率答"往里还是往外"）
- **"不可用"产物的负贡献标注**（推论 1 要看得见）
- **三级分配生效时的可见性**（"为什么我的工厂停了" → 必须能回答"因为氧先给了生命维持"）

> **一条与 A1/A3/A5/A6 一致的取向**：**给可核对的细节，而不是给一个结论。**
> 例如不要只说「氧不足」，而要能回答「**是被存贮吃掉的，还是被那台新机器吃掉的**」。
