## Summary

定义**"这份东西能用吗"**（三档分级）与**"怎么把它变回能用"**（分离提纯产线）——
并把"提纯"从**一个开关**变成**一条玩家搭出来的产线**。

## Overview

### ① 三档分级（**用户早先已拍**）

概念文档原话：
> **「失败从二元悬崖改成分级**（`≥ 99.9%` 直接可用 · `99.0–99.9%` **需要你接一条分离产线** ·
> `< 99.0%` 太脏，**分离也救不回来，只能存贮或销毁**）——
> 注意本作**没有货币**，它不会"被低价卖掉"。」

**三档的含义不是"好坏"，而是"出路不同"**：

| 档位 | 出路 |
|------|------|
| **可用（≥99.9%）** | **交付**（直接进入下游或生命维持） |
| **需精制（99.0–99.9%）** | **必须接一条分离产线**才能用（否则只能存贮/销毁） |
| **不可用（<99.0%）** | **只剩存贮 / 销毁** —— **分离也救不回来** |

### ② 提纯**不是开关**，是一条玩家搭出来的**分离产线**（**用户原话**）

> 概念文档原文：**「提纯不是开关，是一条玩家搭出来的分离产线」**
> （用户原话：「**让玩家设计产线分离污染物，提纯来让产物变为可用**」）。

**被污染的产物流接进【分离操作原语】，产出两股**：
**一股可用的产物** + **一股含氯物流**（后者必须被去处 —— 见 B4 的表）。

### ③ 分离路线本身是**设计题**（概念文档已给了三角）

> **「回收率、耗氧、以及产生多少需要处理的污染物，三者互相拉扯」**
> —— 例：**碱洗**回收率最高，**但产生含氯废液**；**吸附**最费氧，**但污染残留最少**。

**这三者构成一个权衡三角**，与 A6 的代价三角同源（但**维度不同**：这里是分离工艺的选择）。

### 四条承重约束

**① 三档的阈值是【硬规格】—— 它不会为玩家让步。**
> 概念文档：「**痕量即毁规格**：T0 实测纯度落在 **99.70–99.95%**，而规格是 **99.9%** →
> **不合格的整批不计入合格产量**。」
> → **这是"严谨"最直接的体现**：99.85% 与 99.95% 在别处可能都叫"很纯"，**在这里一个可用一个不可用。**

**② 分离**有**明确的输入与输出**（不是"降低污染度"）。**
> 因为 B2 已定：**污染是一组【具体混进来的化合物】**（不是"一个污染值"）。
> → 所以分离**有目标**：你可以专门分离掉 Cl₂，而不是笼统地"提纯"。

**③ 提纯**不是免费的，也不是瞬间的**。**
> 分离要**耗氧**（Core Mechanics #6：一切代价以氧计），且要**接成产线**（占设备与管线）。

**④ 分离产生的废物流必须被去处**（这是本作的"收口"）。
> 概念文档：**「那股含氯物流必须被去处」** —— 三条出路全在 B4 的表里（存贮 / 销毁 / **送回电解池**）。

### 边界（它不是什么）

- **不是污染的来源** —— 那是 **B2**（B2 说"污染从哪来"，B3 说"它意味着什么、怎么办"）。
- **不是代价值的计算** —— 那是 **A6**（B3 定义分离的**三方拉扯**，A6 把代价表达出来）。
- **不是产物的出路表** —— 三档的**出路**在 **B4** 的表里（B3 只定**档位边界**）。
- **不是百科** —— 怎么讲给玩家听属 **B7**。
- **不是 HUD** —— 读数怎么排属 **B11**。

**三档阈值：全局统一**（已定，①）—— 它是 B4 那条"双角色同一个数字"的必然推论（澄清 2）。

**T1 的分离原语：三个**（冷凝 / 碱洗吸收 / 吸附，已定 ④）。

**能否串联：允许**（已定 ⑦），但 **⑥ 的地板是绝对的** —— 两者关于不同对象（澄清 1）。

**档位边界取法**：与 A2 的 `[a, b)` 约定一致 ——
`[99.9%, ∞)` 可用 · `[99.0%, 99.9%)` 需精制 · `[0, 99.0%)` 不可用。
**注意 99.9% 恰好达标算【可用】**（概念文档说"规格是 99.9%"，达标即合格）。

## Player Fantasy
**方向：**「**差 0.05% 就是不能用。**」

这是 P2「严谨是美感」**最锋利**的一处 —— 也是**最能伤人**的一处：
**玩家会第一次遇到"我的东西看起来很对，但规格不认"。**

而它的补偿是：**规格是公平的、可读的、可以在事前算出来的** ——
玩家**不该在事后**才知道自己的产物不合格（那会变成"暗算"，而 B2 已把"不能是暗算"定为纪律）。

**反例**：玩家建好产线、跑了一段时间，才发现纯度 99.85% —— **差一点，而他从头到尾不知道规格是多少。**
**那不是"严谨的惩罚"，那是"没告诉他规则"。**

**正确的手感应是**：玩家**在动手之前**就能算出"这套条件大概落在哪一档"，
然后在**接近边界时**感到紧张（那才是"严谨的美感"发生的地方）。

## Detailed Design

### Core Rules
| # | 规则 | 状态 | 依据 |
|---|------|------|------|
| ① | **三档阈值【全局统一】**：`≥99.9%` 可用 · `99.0–99.9%` 需精制 · `<99.0%` 不可用。 | ✅ 已定 | 用户早先拍过（概念文档 line 93）+ 本轮确认为全局统一 |
| ② | **档位由【主产物占比】决定**（A6 给的定义）—— **B3 只定阈值与分级**。 | ✅ 已定 | A6 的契约 |
| ③ | **提纯 = 接一条分离产线**（不是点一个"提纯"按钮）。 | ✅ 已定 | 概念文档 + 用户原话 |
| ④ | **三个分离原语**：**冷凝 / 碱洗吸收 / 吸附** —— 它们必须在"**回收率 / 耗氧 / 废物流量**"三角上**排序不同**。 | ✅ 已定 | 用户拍板（T1 做 3 个） |
| ⑤ | **分离产出两股**：可用的产物 + **含氯物流**（后者必须被去处 —— 三条出路在 B4 的表里）。 | ✅ 已定 | 概念文档 |
| ⑥ | **`<99.0%` 不可救** —— 不得存在任何"变回可用"的路径（**包括稀释**）。 | ✅ 已定 | 概念文档明写"分离也救不回来" |
| ⑦ | **允许串联分离**（分离完可再接一次）—— **且与 ⑥ 不矛盾**，见下方澄清。 | ✅ 已定 | 用户拍板 |
| ⑧ | **不合格的产出不计入合格产量**，**但也不得凭空消失**（它变成待处理的物流）。 | ✅ 已定 | 概念文档"痕量即毁规格" |

### 澄清 1：⑥ 与 ⑦ 为什么不矛盾（**这是最容易实现错的一处**）

两条规则看起来会撞：

| 规则 | 说法 |
|------|------|
| **⑥** | `<99.0%` **不可救** —— 分离也救不回来 |
| **⑦** | **允许串联**（分离完再分离） |

**它们是关于【不同对象】的：**

> **⑥ 的那道地板是对【输入】说的** ——
> **一份低于 99.0% 的物流，无论怎么分离、分离多少次，都变不回可用。**
> **⑦ 的串联是针对【地板之上】的物流** ——
> 一份 99.5%（需精制）的物流，**可以**通过串联两次分离做到 99.95%。

**所以两句可以同时为真**：**地板是绝对的，而地板上方是可以用工序堆出来的。**

> ⚠️ **若这一条不写清**，实现者会走两个方向之一，而**两个都错**：
> - 把 ⑥ 读成"只要串联就总能救" → **地板消失**，"不可救"这一档就没有意义了；
> - 把 ⑦ 读成"一次分离定生死" → **"分离产线"这个词名不副实**（那它就只是一个开关）。

### 澄清 2：① 为什么选【全局统一】（而不是逐产物不同）

**因为它与 B4 的一条硬约束一致**：

> B4 定了 **氧的双角色共用【同一个数字】**（生命维持 + 工业能源）。
> **若规格逐产物不同**，那就等于说"生命维持用的氧"与"工业用的氧"**是两个标准** ——
> 而那**正是 B4 明令禁止的"拆成两个池"的变体**（不是拆池，而是拆规格）。

**所以全局统一不只是"简单"，它是那条约束的必然推论。**

（并且它与概念文档那句单数措辞一致：**"而规格是 99.9%"** —— 它没有说"各自的规格"。）

### 澄清 3（F-B3-1）：**"主产物"是【声明】出来的，不是算出来的** —— 纯度是**相对**的

"主产物占比"里的"主"从哪来？这决定了"纯度"是不是一个成立的概念。

**若它靠"谁占比最大谁就是主"来算** → **纯度会随物流成分变化而反复改名**，
档位就没有意义了（同一份物流一会儿是"水 99.5%"、一会儿是"氧 60%"）。

### 答案：它由【产出它的那一步】声明 —— 而 A2 的步骤记录里已经有这个字段

A2 的步骤记录形状里就有 **`outputs.主产物`** ——
所以**一份物流的"主产物"就是产出它的那一步所声明的那个**。

> ### 因此：**纯度是【相对于目标产物】的，不是物流的固有属性。**
> 同一桶东西，**当作"水"看是 99.5%，当作"含氯溶液"看就是 1.2%** —— 两个都对，
> 因为**纯度这个词必须带一个"相对于什么"**。

**这条推论有两个直接后果**：
1. **B3 的档位是"相对于某个目标"的** → 界面与百科都必须说清"这份物流被当作什么在判"（B11/B7）；
2. **没有声明主产物的物流**（例如从 B6 混装罐里按比例取出的那股）
   → **它没有档位** —— 它不是"某个产物"，**它需要先被分离**（这正是 B3 存在的意义）。


### States and Transitions
**主判断：不适用**（同 A2/A6 —— **明确写出，不留空**），但要**说清理由，且与那两次不同**：

- **A2 写"不适用"**是因为它是**只读数据**；
- **A6 写"不适用"**是因为它是**无状态的表达层**；
- **B3 写"不适用"**是因为它是**一套规则 + 一条产线** —— 它不持有运行时状态，
  而"档位"是**相对于目标产物的、按需计算的**（澄清 3），**不是被存起来的字段**。

> **⚠️ 这条推论很重要**：既然档位是**算出来的**而不是**存起来的**，
> 那它**永远不会过期** —— 上游一变，档位就跟着变，不需要"刷新"。
> **反过来说：任何把档位缓存下来的实现都会引入一处不一致的入口。**

## Formulas
> **本节原则（同 A3–A6）：B3 定义的是【判定与工序】，不是新化学。**

### ① 纯度（相对目标产物）

```
纯度(物流, 目标) = 目标产物的量 ÷ 该物流的原子总数        ← A6 给的定义；目标由产出它的步骤声明（澄清 3）
```

### ② 档位映射（边界与 A2 的 `[a, b)` 约定一致）

```
纯度 ∈ [99.9%, ∞)        -> 可用
纯度 ∈ [99.0%, 99.9%)    -> 需精制
纯度 ∈ [0, 99.0%)        -> 不可用（分离也救不回来）
```

### ③ 分离的产出分配

```
输入 -> { 可用产物: 量 × 回收率,  废物流: 量 × (1 − 回收率) }
```
**三个原语在三个维度上的位置不同**（这是"设计题"的落点）：

| 原语 | 回收率 | 耗氧 | 废物流量 |
|------|--------|------|----------|
| **碱洗吸收** | **最高** | 中 | **最高**（产生含氯废液） |
| **吸附** | 中 | **最费氧** | **最少**（污染残留最少） |
| **冷凝** | 待定 | 待定 | 待定 |

> **⚠️ 上表只填了两行**，因为概念文档只给了碱洗与吸附的对比。
> **冷凝的位置必须由它在三角上与另两者【排序不同】来确定** —— 否则 ④ 就不成立。

### ④ 串联（⑦）

```
物流 --分离--> (可用产物, 废物流) --若仍不达标--> 再分离
地板：输入纯度 < 99.0% 时，无论串联多少次都不可用（⑥）
```

## Edge Cases
| 边界 | 行为 | 依据 |
|------|------|------|
| **纯度恰好 = 99.9%** | **算可用**（达标即合格 —— 概念文档说"规格是 99.9%"） | ② 的 `[a, b)` 约定 |
| **纯度恰好 = 99.0%** | **算需精制**（99.0 属于 `[99.0, 99.9)`） | 同上 |
| **一份物流含多种产物** | **纯度必须带"相对于什么"**；**没有声明主产物的物流没有档位，需先分离** | 澄清 3 |
| **分离后的产物仍不达标** | **可以再分离**（⑦）—— 只要它的输入纯度 ≥ 99.0% | ⑦ + 澄清 1 |
| **分离产生的废物流又要处理** | 允许（它就是普通物流）；它通常已低于地板 → 只剩 B4 表里的存贮/销毁 | B4 的表 |
| **`<99.0%` 能否靠稀释变可用** | **禁止** —— ⑥ 明写"分离也救不回来"，**稀释更是变相规避** | ⑥ |
| **三个原语在三角上排序相同** | **视为失败** —— 那样"分离路线本身是设计题"就不成立 | ④ |

## Dependencies

**上游 2 个**：B2 · A1。
**下游 3 个**：见 §Interactions（**本处不重复** —— 同全项目纪律）。

### 两条由定位推出的性质

1. **它是唯一一个"必须让玩家事前就能理解一个数"的系统。**
   99.9% 这个数如果**只能在事后才知道**，B3 就从"严谨"变成"运气" ——
   而概念文档把"**不能是暗算**"定为纪律。
   → **所以"可事前估算"不是界面美化，而是 B3 正确性的前提。**
2. **它是【污染】与【代价】的汇合点。**
   B2 说"污染是什么" → **B3 说"它意味着什么"** → B4 说"那该怎么办（出路）"。
   → 三者是一条链，**任何一环缺失都会让另外两环失效**（例如：没有 B3，B2 的污染就无法变成决策）。

## Tuning Knobs

| 项 | 范围 | 默认（暂定） | 说明 |
|----|------|--------------|------|
| **三档阈值** | — | **99.9% / 99.0%** | **全局统一**（①）；是否随 T1 调整见 Open Questions |
| **三个原语的回收率** | 0–1 | 待定 | 三角的第一维（碱洗最高） |
| **三个原语的耗氧** | 氧 / 单位 | 待定 | 三角的第二维（吸附最费） |
| **三个原语的废物流量** | 比例 | 待定 | 三角的第三维（吸附最少） |
| **一次分离的纯度提升幅度** | — | 待定 | 决定"要串几次才够" |

> ⚠️ **边界**：纯度的定义（分子/分母）属 **A6** · 出路与代价属 **B4** · 污染来源属 **B2** ——
> **B3 只定义"判定与工序"**。

## Acceptance Criteria

**六条，每条都可独立检验。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **边界测试** | 纯度恰好 99.9% → **算可用**；恰好 99.0% → **算需精制**（不能两档都算） |
| **2** | **不可救测试** | `<99.0%` 的物流**不得存在**任何变回可用的路径 —— **包括稀释** |
| **3** | **产线测试** | 提纯必须是**接出来的**（不能靠一个按钮）—— 承重约束 ② |
| **4** | **不合格不计入测试** | 不合格产出**不得**混进合格产量，**但也不得凭空消失**（变成待处理物流） |
| **5** | **三角存在性测试** | **三个**原语在"回收率 / 耗氧 / 废物流量"上的**排序各不相同** —— 否则 ④ 不成立 |
| **6** | **相对性测试（F-B3-1）** | 同一份物流作为**不同目标**时有不同档位；**没有声明主产物的物流没有档位**（需先分离） |

> **第 6 条是澄清 3 的可测形式**：它保证"纯度"不是一个会被误当成固有属性的东西。

## Game Feel

`[待定]` —— 方向：见 §Player Fantasy（"差 0.05% 就是不能用"）。
**它的手感是双刃的**：
- 一次**恰到好处**的分离设计成功达标 → 强满足感（P2 的美感在这）；
- 一次**差一点点**的不合格 → 强挫败感。
**而两者的分界必须清晰可预判** —— 否则它就从"严谨"变成"运气"。
