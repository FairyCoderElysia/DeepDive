## Summary

决定**一个 tick 里装得下多少** —— 并给"规模上限"这个此前一直没人认领的数**一个归属**。

## Overview

### 它是**前几轮攒下来的债务的汇总点**

| 来源 | 移交内容 |
|------|----------|
| **A1** | 「典型 tick 原子数量级 = **万级**（~167 中 ～ ~16,700 大）」，**交 B19 当第一个性能预算** |
| **A2** | 「预算应该花在**原子池与管网 tick** 上，**不必为 A2 的查询留额度**」 |
| **A3** | 层内联立 + 优先级 + **迭代到不动点（上限 8）** |
| **A5** | 「**一次求值要做什么**（含**嵌套不动点**）」· 「**100–500 条边 / 50–200 个节点**；**上限交 B19 定**」 |

### 🎯 它要算的核心量：**那个嵌套不动点**

**A5 的⑧与 A3 的求解器合起来给了一个最坏情况**（我在 A5 那轮就标了它是 B19 的 #1 问题）：

```
最坏 ≈ 环的迭代轮数 × 层数 × 层内迭代轮数
        ↑ A5 的环不动点   ↑ A3 的层   ↑ A3 的层内不动点（上限 8）
```

**而 A5 已定：环的不动点【嵌套在】A3 的层不动点内。**

### ⚠️ 三笔账是【正交的】—— 必须分别预算（A5 的 ⑧ 已定）

| 维度 | 规模随什么增长 |
|------|----------------|
| **A1** | **原子数**（万级 / tick） |
| **A3** | **机器数** |
| **A5** | **管段数**（100–500 边） |

> **→ 三者不同维度** —— **不得用一个数估算全部**（A5 给 B19 的契约原话）。

### ⚠️ 而它的第一个基准是【假设】不是实测（A1 的警告，必须继承）

> A1 原话：**「大工厂量级（1000 份/秒）是假设，不是实测** ——
> 它决定"万级原子/tick"这个基准，而**该基准直接决定 B19 的性能预算**。
> **需在飞船规模与玩家基地体量定下来之后复核**（**若错一个数量级，B19 的预算全错一个数量级**）。」

**→ 所以 B19 的预算必须【写明它的假设】，并且在假设变时能被复核** —— 否则它会变成一个假的精确数。

### 边界（它不是什么）

- **不是求值语义** —— 那是 **A3/A5**（B19 决定"装得下多少"，**不决定"算出来是什么"**）。
- **不是渲染性能** —— 那属 B12/B13/B14（**表现形式**）。
- **不是 A2 的查询性能** —— A2 已明确"不必为它留额度"。
- **不是难度系统** —— 它不改游戏规则，**只改"能跑多大"**。

**超预算时的行为**：✅ 已定 —— **tick 变长（世界走慢）**，不降级（③，澄清 1）；
且**它有一个下限 + 告警**（澄清 4，F-B19-1）。

**规模上限**：✅ 已定 —— **无硬上限，但有设计目标**（④，澄清 2）。

**T1 交付到什么程度**：✅ 已定 —— **标杆 + 实测 + 框架，不承诺数字**（⑤，澄清 3）。

## Player Fantasy
**方向：**「**它一直在跑。**」

技术系统的幻想是**否定式**的：**玩家不该感到它的存在** ——
而当玩家感到它（卡顿、跳帧、工厂"停了一下"）时，**它就已经失败了**。

**⚠️ 但 ③ 给了这条幻想一个特例**：**当世界走慢时，玩家是会感到的** ——
而那不是失败，那是**唯一的诚实选项**（澄清 1）。
**所以它的目标要改写为**：**"玩家感到的每一件事，都必须是真的"** ——
**走慢是真的，卡帧是 bug。**

## Detailed Design

### Core Rules
| # | 规则 | 状态 | 依据 |
|---|------|------|------|
| ① | **三笔账分别预算**（原子数 / 机器数 / 管段数 —— **正交**）。 | ✅ 已定 | A5 的 ⑧ |
| ② | **预算的形状必须包含那个【嵌套不动点】**（环 × 层 × 层内）。 | ✅ 已定 | A3 的 ④ + A5 的 ⑥ |
| ③ | **超预算 → tick 变长（世界走慢）** —— **不降级、不近似**。 | ✅ 已定 | 用户拍板（见澄清 1） |
| ④ | **无硬上限，但有【设计目标规模】**（A5 给的 100–500 边 / 50–200 节点）。 | ✅ 已定 | 用户拍板（见澄清 2） |
| ⑤ | **T1 交付 = 标杆场景 + 真机实测数字 + 预算框架** —— **不承诺具体性能数字**。 | ✅ 已定 | 用户拍板（见澄清 3） |
| ⑥ | **预算必须写明它的假设**（"万级原子/tick"来自一个**假设**）。 | ✅ 已定 | A1 的警告 |
| ⑦ | **不得改变求值结果** —— 只改"装得下多少"，**不改"算出来是什么"**。 | ✅ 已定 | A3/A5 的边界 |

### 澄清 1：为什么是"**世界走慢**"而不是"降级" —— 而这是本作**独有的一条自由**

别的工厂游戏面对超预算只有两个选择：**降级**或**卡帧**。**而本作有第三个**：

| 方案 | 它破坏什么 |
|------|------------|
| **降级**（跳求值 / 复用上一 tick） | **破坏 P2 的确定性底线** —— "同存档 + 同操作序列 → 结果必然复现"（B5 的 ⑨ 也是这条） |
| **卡帧** | 破坏**手感**（而手感是玩家能感到的） |
| **世界走慢** ✅ | **什么都不破坏** —— 因为**本作无时限** |

> ### ⚠️ 关键是"世界走慢" ≠ "卡帧"
> **前者是【游戏内时间】变慢**（渲染仍流畅、**每个 tick 仍然精确**）；
> **后者是【帧率】掉。**
>
> **它的代价是"玩家会觉得世界变慢了"** —— 而那是**一个可被感知但可解释**的代价（不同于"卡"）。

### 澄清 2：**"无硬上限"与"有设计目标"是两件事**（很容易被合成一个）

| | 它是什么 | 它的作用 |
|---|----------|----------|
| **硬上限** | **一条规则** | **拒绝**玩家的建造 |
| **设计目标规模** | **一个优化目标** | 让"**够不够快**"这个问题**有答案** |

> **→ 选 ③ 之后就不需要硬上限**（世界自己会慢）；
> **但性能工作仍然需要一个目标** —— 否则"**优化到什么程度**"这个问题无法回答。
>
> **这与 A1 那条"写明假设"是同一种诚实**：**承诺与目标必须分开写。**

### 澄清 3：为什么 **T1 不承诺具体数字**

> A1 的警告原文：**「大工厂量级（1000 份/秒）是假设，不是实测……
> 若错一个数量级，B19 的预算全错一个数量级」**。
>
> **→ 所以 T1 若写一个确定值，就是【把假设钉成事实】** —— 而那**正是 A1 明确警告过的事**。
>
> **替代方案**：T1 交付
> **① 一个标杆场景**（可重复运行）· **② 在真机上测出来的数字** · **③ 预算框架**。
> **这样下一个数量级的变化只会【更新数字】，不会【推翻结构】。**

### 澄清 4（F-B19-1）：**"世界走慢"必须有一个【下限】，且到下限时必须告警**

③ 选了"世界走慢"之后，立刻产生一个问题：**它能慢到多慢？**

**若没有下限**，它会把"超预算"变成一个**无声的无限恶化**：

```
规模继续变大 --> 世界继续变慢 --> ... 直到不可玩
                                  ↑ 而【玩家不知道为什么】
```

**→ 那正是"不能是暗算"要禁止的形态**（同 B2 的失败模式纪律）。

### 修法：**下限 + 告警**（而它不是硬上限）

| | 是什么 |
|---|--------|
| **下限** | 慢到某个程度就不再更慢（**保证它仍然可玩**） |
| **告警** | 到下限时**明确告诉玩家**："你的工厂已经超出这台机器的处理能力" |
| **⚠️ 它【不是】硬上限** | **不拒绝建造** —— 只是**诚实**（同 A1 的"写明假设"、澄清 2 的"承诺与目标分开"） |

> **区别很关键**：**硬上限说"你不许造"；下限 + 告警说"你可以造，但要知道会发生什么"。**
> 而本作的立场（P3 玩家主导 + "不能是暗算"）指向**后者**。


### States and Transitions
| 状态 | 含义 |
|------|------|
| **正常** | 工作量 ≤ 预算 |
| **接近目标** | 工作量接近**设计目标规模**（优化工作的参照点，**不是**玩家的界限） |
| **超预算** | **世界走慢**（tick 变长） |
| **到下限** | **不再更慢 + 告警**（澄清 4） |

**⚠️ 一条必须写清的**：**"世界走慢"必须是可感知但可解释的** ——
否则玩家会把它读成"游戏卡了"（而那不是我们想传达的）。
→ **所以告警（或某种可见的指示）不是可选项，而是 ③ 的必需品。**

## Formulas
### ① 工作量式（**三笔账分开**）

```
工作量 ≈ f(原子数) + g(机器数) + h(管段数 × 嵌套轮数)
                                        ↑ 环轮数 × 层数 × 层内轮数
```
**三笔账【正交】**（A5 的 ⑧）—— **不得用一个数估算全部**。

### ② 预算判定与超限行为

```
若 工作量 <= 每 tick 预算:   dt = 正常 dt
否则:                        dt = 正常 dt × (工作量 / 预算)      ← 世界走慢
                             且 dt 不超过【下限】（澄清 4）
                             到下限时 -> 告警
```

### ③ 不收敛的处理（**继承 A3/A5**）

```
若 迭代到上限仍不收敛:  按 A3/A5 的规则（上限 + 告警）
```
**B19 不重新定义它** —— 只把它计入工作量。

### ④ 预算的假设（**必须写明**）

```
预算基准 = "万级原子 / tick"      ← 【假设】，不是实测（A1 的警告）
```

## Edge Cases
| 边界 | 行为 | 依据 |
|------|------|------|
| **走慢到下限** | **不再更慢 + 告警**（不拒绝建造） | 澄清 4 |
| **嵌套不动点不收敛** | 按 **A3/A5** 的上限 + 告警 —— **B19 只把它计入工作量** | ② |
| **三笔账同时超** | 逐笔计入（**它们正交**）—— 不得只算最大的一笔 | ① |
| **玩家在巨慢的世界里操作** | **允许** —— 操作不受帧率影响（**渲染仍流畅**） | 澄清 1 |
| **预算基准的假设被推翻** | **只更新数字，不推翻结构** | 澄清 3 |
| **某台机器被删掉** | 工作量随之下降 → 世界**可以快回来** | ③ |

### 两条由定位推出的性质

1. **它是唯一一个"以【机器】为对手"的系统。**
   别的系统的约束都来自**游戏设计**（支柱、支柱间的张力）——
   **而 B19 的约束来自【硬件】。**
   → 所以它是本项目唯一一处**玩家体验会被"这台电脑"影响**的地方 ——
   而 ③（世界走慢）正是把这件事**做成诚实的**、而不是做成"卡"。
2. **它是【债务汇总点】。**
   A1/A2/A3/A5 各自把"性能相关的事"推给了它（且 A2 明确说"不必为我留额度"）。
   → **所以它的第一件事不是设计，而是【把四笔账合成一个可测的基准】。**

## Acceptance Criteria

**六条。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **正交测试** | 三笔账**必须分别测量**（不得用一个数估算全部） |
| **2** | **诚实测试** | 预算**必须写明它的假设**（"万级原子/tick"是假设不是实测） |
| **3** | **不改结果测试** | B19 的机制**不得改变求值结果** —— 同样的输入 → 同样的化学 |
| **4** | **确定性测试** | 超预算时的行为**不得引入随机性** —— **且"世界走慢"不得改变任何一次求值的结果** |
| **5** | **最坏情况测试** | 预算必须覆盖**嵌套不动点的最坏情况**，而不是平均情况 |
| **6** | **下限与告警测试（F-B19-1）** | 走慢**必须有下限**，且**到下限必须告警** —— **且它不是硬上限（不拒绝建造）** |
