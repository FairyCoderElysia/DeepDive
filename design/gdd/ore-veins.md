# C2 · 矿脉与开采（Ore Veins & Extraction）

> **Status**: **Approved**（2026-10-02 评审通过 —— 见 `design/gdd/reviews/ore-veins-review-log.md`）
> **Category**: World · **Layer**: Feature · **Priority**: T3
> **Depends On**: **C1**（深度的分布规则）· **A1**（元素表与"是否矿脉专属"字段）
> **被依赖**: **2 个**（C3 飞船与零件 · C4 程序生成）
> —— 口径：`design/gdd/systems-index.md` 的 `Depends On` 列含 `C2` 的行数。
> **设计顺序**: Feature Layer 第 5 项

## Summary

定义**唯一的非海水元素来源** —— 而它是**用户明确约束**的实现：
> **「深海不是选择项，是【必须项】。前期可以依靠提炼海水获取元素，
> 但【有些元素需要深海矿脉才能获取】，【后期大规模获取元素也必须依靠深海矿脉】。」**

## Overview

### 它承担的是 P4，而 P4 是唯一被明确标为"必须"的支柱

概念文档 P4 相关原话（用户明确约束，2026-10-02）：
> **「深海不是选择项，是必须项。」**

**而它有两条腿**（都由 C2 落地）：

| 腿 | 概念文档 |
|----|----------|
| **元素种类** | **「有些元素需要深海矿脉才能获取」** —— 存在**仅矿脉可得**的元素 |
| **通量** | **「后期大规模获取元素也必须依靠深海矿脉」** —— 海水**永远放不大** |

> **两条腿缺一条，"必须下潜"就不成立**：
> 只有种类缺 → 玩家拿完关键元素就回表层了；
> 只有通量缺 → 玩家可以用海水慢慢堆到后期。
> **→ 两条都必须有**（C1 的 ④ 已定；C2 是它的落点）。

### ⚠️ 一条【无人认领】的缺口（本系统必须接住）

**概念文档 Risk #9（line 425）原话**：
> **「元素来源分层的【具体划分尚未定】—— 哪些元素海水可得、哪些仅矿脉可得，
> 直接决定『必须下潜』是真是假，也决定【整棵产物树的形状】。
> → 归属：元素池与化学计量系统的 GDD（`/design-system`），不在概念层拍。」**

**而这条指派【没有被执行】** —— 它的路径是：

| 谁 | 做了什么 |
|----|----------|
| **概念文档** | 指派给「元素池与化学计量系统的 GDD」 |
| **A1（元素池）** | 只造了**钩子**：字段集里有「**是否矿脉专属**」，并写明「海水 8 元素 + 矿脉按需新增」——**但没填清单** |
| **A1 → C2 的契约** | 「不得假设**所有元素都能从海水得到**」 |
| **C1 → C2 的契约** | 「**矿脉的分布规律（哪些元素在哪些深度）**」 |
| **→ C2** | **清单落在本系统手上，而前面每一环都以为别人做了** |

> **⚠️ 这一条必须在本 GDD 里被显式接住** —— 因为它是"必须下潜"真假的分界线，
> 而它一路无人认领（**不是"漏写"，是"指派了但没人执行"**）。

### 边界（它不是什么）

- **不是深度的形状** —— 那是 **C1**（C2 消费"哪些深度"）。
- **不是元素的化学属性** —— 列表与原子量属 **A1/A2**（C2 定义**来源**，不定义化学）。
- **不是程序生成** —— 那是 **C4**（C2 定义"矿脉是什么"，C4 定义"怎么生成它"）。
- **不是飞船零件** —— 那是 **C3**（C3 依赖 C2 拿材料）。

**开采是"机器"还是"来源"**：✅ 已定 —— **源节点**（④，澄清 1）。

**"高代价"的代价是什么**：✅ 已定 —— **设备与基建**（⑤，澄清 2）；
而**它的另一半是"挖到了还得炼"**（澄清 4）。

**清单归谁定**：✅ 已定 —— **C2 给判据 + 候选清单，不锁死**（⑥，澄清 3）。

## Player Fantasy
**方向：**概念文档已给了一句很准的 ——
> **「回来的理由：下一个产物需要你【下潜】（深度是唯一的大宗矿源）→ 你总想"再开一层"」**

它的情绪**不是"我挖到宝了"，而是【下一个产物在下面】**
—— **矿脉是"理由"，不是"奖励"。**

而它与 **C1 的"深度是可见的压力"**配合起来才是完整的：
**越下去越压抑，但越下去越有理由。** 两者一个给阻力、一个给动力。

**⚠️ 而澄清 4 给这份幻想加了一句关键的**：**你挖到的不是金属，是矿石** ——
**所以"下面有我要的东西"这句话的完整版是"下面有我要的东西的原料"。**

## Detailed Design

### Core Rules
| # | 规则 | 状态 | 依据 |
|---|------|------|------|
| ① | **矿脉是唯一的非海水元素来源** —— 它有**两条腿**（种类 + 通量），**缺一条 P4 就不成立**。 | ✅ 已定 | 用户明确约束 |
| ② | **只认「仅矿脉可得」的元素** —— **种类腿**。 | ✅ 已定 | 概念文档 line 291 |
| ③ | **后期大规模获取元素也必须靠矿脉** —— **通量腿**。 | ✅ 已定 | 用户原话 |
| ④ | **矿脉是一个【源节点】**（像海水一样）—— **不是一种操作原语**。 | ✅ 已定 | 用户拍板（见澄清 1） |
| ⑤ | **C2 的代价 = 设备与基建代价** —— **带宽与耗氧已由 C1/B4 收了，不重复收费**。 | ✅ 已定 | 用户拍板（见澄清 2） |
| ⑥ | **「仅矿脉可得」的清单：C2 给【判据】+【候选清单】，但【不锁死】**。 | ✅ 已定 | 用户拍板（见澄清 3） |
| ⑦ | **矿脉会枯竭吗** | `[待确认]` | 见 §Open Questions（与 P5 有关） |

### 澄清 1：为什么矿脉必须是【源】而不是【机器】

| 理由 | 说明 |
|------|------|
| **① 对称性** | 概念文档把海水与矿脉当成**一对**：**「海水无限但低通量；矿脉高密度但高代价」**。**它们应该是同一类东西的两个实例**，而不是"一个是环境、一个是机器" |
| **② 6 个原语里没有"开采"** | 原语是**化学操作**（过滤 / 蒸馏 / 电解水 / 气液分离 / 焚烧 / 燃料电池）—— **开采不是化学操作**，所以它不该被塞进原语 |
| **③ 少一层没有决策含量的东西** | 若做成"开采机"，玩家永远只会把它**直接接上** —— 那是**没有决策的中间件** |

### 澄清 2：C2 的代价必须是**它自己那一份**（不重复收费）

概念文档说「矿脉高密度但**高代价**」，但**代价的三个维度里有两个已经被别人收了**：

| 代价维度 | 归谁 | 状态 |
|----------|------|------|
| **带宽** | **C1**（越深带宽越低） | ✅ 已定 |
| **耗氧** | **B4**（越深耗氧越高） | ✅ 已定 |
| **设备与基建** | **C2** ← **这是它自己的那一份** | 本系统 |

> **⚠️ 若 C2 把三者都写一遍，就会造出【同一事实的两处定义】** ——
> 而本项目**已实测过 6 次**这类漂移事故。**所以 C2 只定义"更深的开采设施更贵 / 等级更高"。**

### 澄清 3：为什么"给判据、但不锁死清单"是对的

概念文档 Risk #9 说这件事「**不在概念层拍**」——
**而它的同一条理由是：那份清单决定【整棵产物树的形状】。**

> **所以：若 C2 现在锁死清单，那就是在错的层拍**（C2 是一份系统 GDD，不是内容表）。
> **但 C2 需要一个判据才能设计** —— 而**判据才是"必须下潜"真假的分界线**：
>
> ### 判据
> **凡【不在海水里】、且【产物树或飞船需要】的元素 —— 就仅矿脉可得。**
>
> **→ C2 给判据 + 候选清单（供 C3/C4 使用），而清单的最终确认留到 T3 内容期。**

### 澄清 4（F-C2-1）：**矿脉给的是【化合物】，不是元素** —— 而中间必须有一条提炼线

**物理上矿就是化合物**（赤铁矿 `Fe₂O₃`、黄铜矿 `CuFeS₂`、磷灰石 `Ca₅(PO₄)₃(F,Cl,OH)` …），
而 **A2 的化合物表本来就以【组成为关键】**（化合物 = 配方，名字只是标签）。

> ### 所以：**挖到矿 ≠ 拿到元素。**
> **中间必须有一条【提炼线】**（还原 / 焙烧 / 浸出 —— 也就是真正的冶金化学）。
>
> **这正是本作想要的那部分**：概念文档的 P2 说「严谨是美感」，
> 而 **"从矿石到金属"是化学史上最重要的那类操作** —— 它不该被一次"开采"吃掉。

**它顺带解释了"高代价"的另一半**：

| 代价 | 是什么 |
|------|--------|
| **带宽 / 耗氧** | 由 C1 / B4 收（澄清 2） |
| **设备与基建** | 由 C2 收（⑤） |
| **提炼线本身** | ⬅ **这一半是"挖到了还得炼"** —— 而它才是化学的部分 |

> **⚠️ 标注**：本条是**从模型推出来的**（矿是化合物 + A2 以组成为关键），
> **不是新加的设计决定** —— 但**它必须被写下来**，否则实现者会把"矿脉"做成"元素水龙头"，
> 而那会**同时废掉冶金这一整块化学**。


### States and Transitions
**每个矿脉有两态**（"枯竭"是 §Open Questions 里的待定项）：

| 状态 | 含义 |
|------|------|
| **已发现** | 玩家到过那里（**B7 的残页由此而来** —— C1 是那条途径的载体） |
| **已开采** | 已接入管网，正在出料 |

**⚠️ 三条与别的系统共用的东西（本系统不重复定义，只引用）**：
- **它出的是【化合物】**（澄清 4）—— 而化合物表属 **A2**；
- **它的通量受【带宽】限制** —— 而带宽属 **C1**；
- **它的代价里有【耗氧】** —— 而耗氧属 **B4**。

### Interactions with Other Systems

**上游 2 个**：C1（深度分布）· A1（元素表）。
**下游 2 个**（口径：`systems-index` 的 `Depends On` 列含 `C2` 的行数 = **2**）：

| 下游 | C2 承诺给它 | **它不得假设** |
|------|-------------|----------------|
| **C3** 飞船与零件 | **飞船材料从哪来**（零件所需的、海水给不了的元素） | 不得假设**飞船材料可以全靠海水** —— 那会让 P4 失效 |
| **C4** 程序生成 | **矿脉是什么**（结构、分布规则、丰度） | 不得假设**矿脉可以随便放** —— 它的**分布规律是 C1+C2 定的** |

**两条已划好的接缝**：
- **与 C1**：**C1 定分布规律，C2 定开采**（C1 的契约原话）。
- **与 A1**：**A1 提供「是否矿脉专属」字段** —— 而**清单本身是那份未执行的指派**。

## Formulas
> **本节原则**：C2 的公式**只有它自己那一份**（澄清 2）—— 其余三个维度都在别人手里。

### ① 矿脉丰度（某元素在某深度的含量）

```
丰度(元素, 深度) = ...        ← 分布规律由 C1 + C2 共同定
```

### ② 开采速率

```
开采速率 = min(矿脉固有速率, 该深度的【带宽上限】, 该深度段的节点优先级)
             ↑ 固有          ↑ 属 C1（C2 不重定义）
```

### ③ 开采代价（**只有设备与基建这一份**）

```
代价 = f(深度, 设施等级)      ← 更深 = 更贵 / 等级更高
```
**带宽与耗氧不在本节**（它们由 C1/B4 收）—— **本系统不重复收费。**

## 候选清单（**判据 + 候选，不锁死** —— ⑥）

**判据**：**凡【不在海水里】、且【产物树或飞船需要】的元素 —— 就仅矿脉可得。**

| 候选元素 | 它开的是什么化学 | 大致归属 |
|----------|------------------|----------|
| **C（碳）** | **有机化学 / 燃料 / 还原剂** —— 化学树最大的一支。**⚠️ 2026-10-03：它升为【能量来源】** —— 深层的能量由**燃料**携带（浅层由光），所以这一类**还原态物质从「候选」变成「必须」**；且其出现深度要与 C1 的**光归零深度**对齐（否则出死区） | 化学 |
| **N（氮）** | **氨 / 硝酸盐 / 含能材料**（连 B5 的灾难） | 化学 |
| **P（磷）** | 磷酸盐 / 肥料 | 化学 |
| **Si（硅）** | 玻璃 / 陶瓷 / 半导体 | 材料 |
| **Fe（铁）** | **结构材料** —— 飞船的主体 | 材料 |
| **Cu（铜）** | 导线 / 合金 | 材料 |

> **⚠️ 这是【候选】，不是定案** —— 清单的最终确认留到 **T3 内容期**（澄清 3）。
> **而它已经足以让 C3（飞船）与 C4（生成）有东西可用。**
> 可能的补充：**Al / Ti / Li**（都属材料侧，视 C3 的零件需求再定）。

## Edge Cases
| 边界 | 行为 | 依据 |
|------|------|------|
| **矿脉枯竭** | `[待定]` —— **与 P5（无时限）直接相关**：若会采完，玩家最终会失去来源 | §Open Questions |
| **同一元素两个来源**（海水 + 矿脉） | **允许**；但**「仅矿脉可得」的元素不得从海水得到任何量** | ② |
| **一个矿脉含多种元素** | **允许**（真实矿就是多元素的）—— **而且它让提炼线更有内容** | 澄清 4 |
| **挖到的矿石直接当产物用** | **不允许** —— 它是**化合物**，**要用就得先炼** | **澄清 4（F-C2-1）** |
| **开采设施在深层受带宽限制** | 走 **C1 的带宽**（**C2 不重定义**） | 澄清 2 |
| **存档时矿脉的已开采状态** | **必须存**（同 B8/B16 的纪律：进度不可重算） | B16 的契约 |
| **玩家在最深层被切断氧气** | 走 **B4 的三级优先**（不是 C2 的事） | B4 的 ③ |

## Dependencies

**上游 2 个**：C1 · A1。
**下游 2 个**：见 §Interactions（**本处不重复** —— 同全项目纪律）。

### 两条由定位推出的性质

1. **它是唯一一个"提供新原料"的系统。**
   别的系统都在**转化**已有物料（A3/B2/B3/B4…）——
   **只有 C2（与海水）在【引入】新物料。**
   → 所以它是**整棵产物树的上游**：**没有它，一部分产物在结构上就不存在。**
2. **它是 P4 的唯一实现 —— 而 P4 是唯一被用户明确标为"必须"的支柱。**
   > 概念文档 Risk #8 的警告是：**没有它，"深海是必须项"在体感上不存在，P4 会退化成一句设定。**
   → **所以 C2 不在，"必须下潜"就只是一句话。**

## Acceptance Criteria

**六条，第 5 条是本轮新增的（F-C2-1）。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **必须下潜·种类腿** | 存在**仅矿脉可得**的元素，且**没有它某类产物结构上做不出来** |
| **2** | **必须下潜·通量腿** | **靠海水无法把产能放大到后期规模**（与 C1 的 T1 义务对应） |
| **3** | **唯一来源测试** | 「仅矿脉可得」的元素**从海水得到的量必须恰好为 0** |
| **4** | **清单已认领测试** | **「哪些元素仅矿脉可得」必须有一处明确归属并已填**（Risk #9 的落点） |
| **5** | **化合物测试（F-C2-1）** | 矿脉产出的**必须是化合物**（不是元素）—— **挖到不能直接用，中间必须有提炼线** |
| **6** | **对称性测试** | **矿脉必须是"源节点"**（与海水同类）—— **不得被实现成一种机器** |
