## Summary

**给工艺起名、把名字挂在机器上、并做出一张能被分享的工艺卡** ——
而它是概念文档里**三条不同诉求的同一个落点**。

## Overview

### 一个系统，三个身份（概念文档的原话）

| 身份 | 原话 |
|------|------|
| **表达（P3）** | 「工艺由玩家连线拼出并**命名**」—— **【命名】是 P3 的第一个词**（line 74） |
| **可见的纪念物** | 「必须有可见的纪念物（**工艺命名、机器铭牌、可复制的工艺卡**，以及终极的飞船），否则表达感会被即时反馈挤没」（line 84） |
| **最强的留存** | 「工艺是玩家自己发明的、命名的 —— **它不能被系统替代**，这是最强的留存」（line 259） |
| **Relatedness 的唯一答案** | 「唯一可能的联结是"**你的工艺被命名、挂在机器上**"」（line 182） |
| **Social（唯一的一点）** | 「（无多人）弱 —— 仅"**工艺卡可分享**"」（line 260） |

> ### **→ 所以它不是"起个名"的小功能** ——
> 它是**表达欲的落地、留存的来源、以及本项目唯一的那一点社交**。

### 为什么它是必要的（概念文档的诊断很准）

> 「Challenge 是**即时**的（接对了就通），Expression 是**延迟**的
> （一条线跑通后"**这是我造的**"才成立）。
> 因此**必须有可见的纪念物**（工艺命名、机器铭牌、可复制的工艺卡，以及终极的飞船），
> **否则表达感会被即时反馈挤没**。」

**→ 这就是 B9 存在的全部理由**：**表达欲需要一个【能被看见的载体】，否则它会被"接对了就通"那个即时反馈吃掉。**

### 它与 B7 的边界（**我在 B7 那轮划好了**）

| 系统 | 它装什么 |
|------|----------|
| **B7 百科** | **事实**（客观规律）—— "这条路线存在" |
| **B9 工艺卡** | **工艺**（玩家的连接方案）—— "**我**发明了这条路线" |

> **→ 两者都"属于玩家"，但归属不同：一个进【知识库】，一个进【作品集】。**

### 而有一条必须守住的（概念文档 line 281）

> **「工艺的命名、复用、优化都归玩家；【系统不替玩家自动寻优】。」**

**→ 所以 B9 不得做任何形式的"评价/推荐/优化提示"** —— 那是它的边界（见提问）。

### 边界（它不是什么）

- **不是百科** —— 那是 **B7**（事实在那边）。
- **不是连线编辑器** —— 那是 **B1**（B9 给工艺**命名与呈现**，不给它编辑）。
- **不是飞船** —— 那是 **C3**（飞船是"终极"的那个纪念物，工艺卡是日常的那个）。
- **不是自动寻优** —— 概念文档明写"系统不替玩家自动寻优"。

**工艺卡能不能导入**：✅ 已定 —— **不能**（③，澄清 1）。

**工艺卡的形态**：✅ 已定 —— **一页可读的卡**（④，澄清 2）。

**铭牌是什么**：名字显示在机器上（②）—— 它是"可见的纪念物"里最日常的那一个。

## Player Fantasy
**方向：**「**这是我造的，它叫这个名字。**」

概念文档的诊断是准确的：**Expression 是延迟的** ——
所以 B9 的任务是**把那个延迟的满足感【物化】出来**（**名字、铭牌、卡**）。

**反例**：表达欲被即时反馈挤没 —— 玩家一直在"接对了就通"，
**却从来没觉得那是自己的作品。**

**而澄清 1 让这条幻想有了一个硬边**：**卡能导出但不能导入** ——
所以**你的工艺只能被看见，不能被复制**。

## Detailed Design

### Core Rules
| # | 规则 | 状态 | 依据 |
|---|------|------|------|
| ① | **玩家可以给工艺命名** —— 而命名是**纯表达**（不带机制作用）。 | ✅ 已定 | 概念文档 line 74（P3 的第一个词） |
| ② | **名字挂在机器上**（"**机器铭牌**"）。 | ✅ 已定 | 概念文档 line 84 |
| ③ | **工艺卡只能导出、【不能导入】**。 | ✅ 已定 | 用户拍板（见澄清 1） |
| ④ | **工艺卡 = 一页可读的卡**（名字 + 拓扑 + 参数 + 代价）—— **不是编码**。 | ✅ 已定 | 用户拍板（见澄清 2） |
| ⑤ | **与 B7 能并列，但不评价**（并列展示事实，玩家自己比）。 | ✅ 已定 | 用户拍板（见澄清 3） |
| ⑥ | **系统不替玩家自动寻优** —— 不做评价 / 推荐 / 优化提示。 | ✅ 已定 | 概念文档 line 281 |

### 澄清 1：为什么"**不能导入**" —— 而它护的正是那句话

概念文档（line 259）：
> **「工艺是玩家自己发明的、命名的 —— 【它不能被系统替代】，这是最强的留存。」**

**而"导入"恰恰就是"可被替代"的实现** ⇒ **若卡片能一键复现，玩家的工艺就不再是他自己的。**

**而"分享"在概念文档里的形态是**（line 107）：
> **「玩家会自发给路线起名、【截图】、分享工艺卡。」**
> → **那是【展示】，不是【安装】。**

> ### **→ 所以"不导入"不是保守，而是【那句话的直接实现】。**

### 澄清 2："一页可读的卡"有一个很好的副作用：**它不需要新的序列化格式**

已有一条约束（A4 定的）：
> **「存档是二进制、JSON 会坏 int64」** —— 所以任何**新的分享格式**都要自己承担那个风险。

**而"一页可读的卡"是【渲染出来的】，不是【序列化的编码】** →
**它根本不碰那条约束** ✅

> ### **→ 于是"不导入"与"不做编码"是同一件事的两面：没有格式，就没有格式的债。**

### 澄清 3：**"能并列、不评价"同时满足两条已定的立场**

| 已定的立场 | 它要求 |
|------------|--------|
| **概念文档** | 「系统**不替玩家自动寻优**」→ 禁的是**寻优**，不是**展示** |
| **B7 的立场**（我写的那条） | 「给一条可行解，并**让玩家看见它的代价**」→ **给数据，不给结论** |

> **→ 两条合起来 = 能并列、不评价** ✅
> **而它与 B7 的"预告结果、不解释原因"是同一条纪律 —— 只是换了一个界面。**

### States and Transitions
工艺有两个状态：

| 状态 | 含义 |
|------|------|
| **未命名** | 图已经能跑 —— **但它还不是"作品"** |
| **已命名** | **它是"作品"了** —— 名字会出现在铭牌与卡上 |

**⚠️ 一条必须确认的**：**未命名的工艺算不算工艺**（能不能保存/分享）？
> 倾向：**能跑就算工艺，但只有命名之后才能出卡** ——
> 因为**卡是"作品"的形态**，而未命名时它还是"一条线"。

## Formulas
**B9 没有数值公式** —— 它是"命名 + 呈现"。

### 但它有一条**结构**：工艺卡上有什么

```
工艺卡 = {
    名字
    拓扑（子图：哪些节点、哪些边）      ← 来自 A5
    参数（每个节点的旋钮值）            ← 来自 A5
    代价（能耗 / 纯度 / 耗时）          ← 来自 A6，由 B7 的立场呈现
}
```

### 与 B7 并列时的结构（**澄清 3 的落点**）

```
并列展示 [我的工艺] 与 [百科的路线] 的【事实】
        —— 不做评价、不给推荐、不标"更优"
```

### 一条明确的"不做"

```
❌ 评分   ❌ 排名   ❌ "建议改用 X"   ❌ 自动寻优        ← 概念文档 line 281
```

## Edge Cases
| 边界 | 行为 | 依据 |
|------|------|------|
| **重名** | **允许** —— 名字是**玩家的表达**，不是唯一键 | ① |
| **改名** | **允许** —— 但要确认"历史名字"是否留痕 | §Open Questions |
| **未命名的工艺** | 能跑就算工艺；**但只有命名之后才能出卡** | §States |
| **工艺卡跨版本** | **不适用**（它不是编码，没有可解析的格式） | 澄清 2 |
| **卡里含玩家未解锁的东西** | `[待定]` —— 见 §Open Questions | —— |
| **别人照截图重连** | **允许** —— 那正是"分享"的形态 | 澄清 1 |
| **有人把卡发到网上** | **允许** —— 而它**不能被一键装回来**（没有格式） | 澄清 2 |

## Dependencies

**上游 2 个**：A5 · B7。
**下游 0 个**：见 §Interactions（**本处不重复** —— 同全项目纪律）。

### 两条由定位推出的性质

1. **它是本项目里【唯一一个"只服务表达欲"的系统】。**
   别的系统要么服务挑战（A3/B5/B19…）、要么服务理解（B7/B10）、要么服务呈现（B11/B12–B14）——
   **只有 B9 的产品是"这是你的作品"这件事本身。**
   → 所以它的评价标准**不是"好用"，而是"玩家会不会觉得自己是作者"**。
2. **它是本项目【唯一一处社交】**（概念文档 line 260："无多人，弱 —— 仅工艺卡可分享"）。
   而 ③ 选了"能导出不能导入"—— **所以这一点社交是【单向的】**：
   **你能让别人看见你的工艺，但别人拿不走它。**
   → **这不是技术限制，而是"作品归属"的设计选择。**

## Acceptance Criteria

**六条。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **可命名测试** | 玩家能**给一条工艺起名**，且名字**挂在机器上** |
| **2** | **不寻优测试** | B9 **不得**给出评价 / 推荐 / 优化提示（概念文档明写） |
| **3** | **不导入测试（澄清 1）** | **工艺卡不得可导入** —— 出现"一键复现"即为失败 |
| **4** | **无格式测试（澄清 2）** | **工艺卡不得是一种可解析的编码**（它是渲染出来的） |
| **5** | **并列不评价测试（澄清 3）** | 与百科并列时**只展示事实**，不得出现"更优/更差" |
| **6** | **留存测试** | **工艺不能被系统替代** —— 若玩家能"一键复现别人的最优解"，即为失败 |
