# A2 · 化合物与反应数据表（Compound & Reaction Data Tables）

> **Status**: Draft（骨架 —— 已定的写清，未定的标 `[待定]`）
> **Category**: Core · **Layer**: Foundation · **Priority**: T1
> **Depends On**: **A1**（元素池与计量）—— 化合物的标识符来自元素表
> **被依赖**: **A3 反应求解器** · **A4 Schema 双解释器与契约校验** · **B7 百科**
> **设计顺序**: 第 2 位（A1 之后；A3/A4 之前）

---

## Summary

存放全项目的**化学事实**：有哪些化合物（其组成 = 元素与原子数）、以及**一个步骤**在什么条件下
能把什么变成什么 —— 但**不负责求解**（求解属 A3）。

## Overview

**它在"数据基座"里的位置**：`systems-index` 明确把基座拆成两半 ——
**A1 是元素，A2 是化合物与反应**，两者共同持有各系统都要引用的数据与 schema；**A3 才求解**。
所以 A2 的产物**是数据，不是算法**。

**它必须满足的两条承重约束**（来自用户原话）：

1. **「每一台机器更像是化学反应中一个或多个步骤，而不是将一个化学反应定死」**
   → 表里存的**不是成品配方**，而是**步骤**。一个产物可以由多条步骤路径达成。

2. **「反应的条件不对，产物纯度不够，都会导致出现意料之外的产物……甚至导致灾难」**
   → 条件（T / P / τ / 催化剂 / 阳极材料）**不是"是否允许"的开关，而是"走向哪一支"的分流器**：
   条件偏离 → 副产物 / 污染 / 灾难通道。**A2 必须能表达分支，而不是只表达"成功"与"失败"。**

**边界（它不是什么）**：
- **不是元素表** —— 那是 A1。
- **不是求解器** —— 那是 A3（限制试剂、化学计量、逐步推进都在 A3）。
- **不是工艺图** —— 那是 A5。
- **不是纯度分级** —— 那是 B2/B3（A2 只提供"哪些副产物会产生"这个事实）。

**表的规模量级（暂定，可调）**：T1 垂直切片约 **20–30 个化合物 / 40–60 条步骤**；
T3 完整愿景约 **100–150 个化合物**。依据：海水只有 **8 个元素、4 个分类组**，
而 T1 只需覆盖「海水 → 起步物资」链 + 6 个操作原语（过滤 / 蒸馏 / 电解水 / 气液分离 / 焚烧 / 燃料电池）
+ 两条失败通道（Cl 污染、结垢）。

**它如何不"把表写死"**：**表里存的是【步骤】，不是成品配方** —— 所以丰富度来自**步骤的组合数**，
而不是表的条目数。**表的规模只需要覆盖"基本步骤"，组合爆炸发生在玩家那一侧**（工艺图属 A5）。
这正是承重约束 #1 在规模上的含义：**一个 40 条的步骤表，可以支撑出远超 40 条路径的玩法。**

**查询频率与性能**：A3 每 tick 查表，但**表在导入后是不可变数据** → 可**预加载进内存哈希表**，查询 O(1)，
**不涉及每 tick 全表扫描**。所以 A2 的查询**不是性能热点**（对比 A1 的原子池遍历才是）。
**这条要交给 B19**：预算应该花在原子池与管网 tick 上，不必为 A2 的查询留额度。

## Player Fantasy
**这一层要给的感受**：**「我造出来的东西，不是游戏替我选的。」**

A2 是玩家看不见的一层，但它的形状决定了玩家能感到多少"化学是真的"。两个具体来源：

- **"先拿到，后命名"** —— 因为组成式是主键（规则 ①），玩家完全可能**先得到一个东西，再在百科里知道它叫什么**。
  **命名不是获得它的前提**，所以"发现"是一种真实发生的体验，而不是脚本演出。
- **失败有指纹** —— 因为不同错法出不同副产物（规则 ④ 的合并式），玩家的失败**带着可辨认的特征**：
  拿到的是氯化物还是结垢，直接指向**哪个旋钮出错了**。对比之下，"你失败了"这种无信息的反馈
  会让玩家只能靠猜 —— 那不是难度，那是噪音。

**服务 P2（严谨是美感）**，并且与 P3（连出来的工艺属于玩家）在数据层相接：
**表提供事实，玩家提供组合。**

**反例（要避免的感受）**：玩家得到副产物时只看到「**废料 +1**」。
那一瞬间，A2 的全部丰富度被压成了一个词 —— **玩家无法从失败中学到任何东西**，
而这会同时废掉"严谨是美感"与"灾难是内容"两条支柱。

## Detailed Design

### Core Rules

| # | 规则 | 状态 |
|---|------|------|
| ① | **化合物 = 组成式唯一标识**。组成（元素 → 原子数）**就是主键**，名字只是显示标签 —— "同一组成两个名字"在结构上不可能。 | ✅ 已定 |
| ② | **一记录一步骤**：输入（元素 / 化合物 + 数量）→ 条件区间 → 输出（化合物 + 数量）。**分支 = 同一输入的多条记录**，各自带**不重叠**的条件区间 —— **分支不是特例，而是区间划分推出来的。** | ✅ 已定 |
| ③ | **条件语义 = 三段区间**：每个旋钮划分 **最优带 / 偏移带（出副产物）/ 越界（出灾难）**。分立、可测。 | ✅ 已定 |
| ④ | **强制配平**：每条步骤的输入输出**元素原子数必须整数配平**，否则**拒绝导入整张表并指出是哪一条**。 | ✅ 已定 |
| ⑤ | **`schema_version`**：与 A1 同口径（版本化；**迁移机制是 A1/A2 共有的未决项**，见 Open Questions）。 | ✅ 已定 |
| ⑥ | **数据与求解分离**：表是**只读数据**；运行时状态（谁在反应、剩多少、A1 的余数累加器）**一律归 A3**。 | ✅ 已定 |
| ⑦ | **旋钮的权威定义在 A1**：A2 只**引用** `param_*`（见 `design/registry/entities.yaml`），**不得另立定义** —— 否则又是同一事实两处定义。 | ✅ 已定 |

### 步骤记录的形状（规则 ②③ 的落地 —— 补 F-A2-2 漏洞）

**每条步骤记录必须显式声明这五组字段**（否则"副产物是什么"无从表达）：

```yaml
- id: 该记录的唯一标识
  inputs:  [ { 元素|化合物, 数量 } ]           # 数量为整数原子数
  conditions:                                  # 每个旋钮一段
    温度:      { 最优带: [a, b), 偏移带: [[c, a), [b, d)] }
    压强/τ/催化剂/阳极材料: 同上
  outputs:
    主产物: { 化合物, 数量 }
    副产物:                                     # 可多条
      - { 化合物, 数量, 系数, 由哪个旋钮偏了导致 }   # ← "由谁导致"这一项是 §Game Feel 的前提
  disaster: false                               # 越界分支置 true
```

**关于"越界 = 灾难"（规则 ③）—— 一条重要澄清**：
**灾难记录同样受规则 ④ 约束，其原子侧必须照常配平**
（真实化学里灾难本身就是反应：燃烧耗 O₂、生成氧化物/水）。
**`disaster: true` 只是【额外的效果标记】；火焰 / 爆炸 / 连锁的表现归 A3 与表现层。**
所以灾难**既是可编辑的数据，又不破坏守恒** —— 这正是规则 ③ 那条推论要的效果。

### 三条值得单独写下的推论

- **① 的推论：发现即玩法。** 既然组成式是主键，**玩家可以在不知道名字的情况下造出并发现一个化合物** ——
  这是 P3「连出来的工艺属于玩家」在数据层的落点。名字由百科（B4）后补，**不是前置条件**。
- **③ 的推论：灾难是一个数据区间，不是一段特殊代码。** 把那句「甚至导致灾难」变成**表里可编辑的一格**，
  正是 P2「灾难是内容」的实现方式 —— 灾难若写在代码里，它就只能有开发者预先想到的那几种。
- **④ 的纪律与 A1 一致**：拒绝整表 + 指出坏行（同 A1 的"原子量为 0 时拒绝整表"决策）。
  理由也一样：**一张带着已知错误的数据表看起来和正常的表毫无区别**，而它的下游（A3）会静默地算错。

### States and Transitions
**不适用** —— 明确写出，不留空。

## Formulas
### ① 原子配平（导入期校验）

```
对每条步骤记录 r：   Σ(输入侧各元素原子数)  ==  Σ(输出侧各元素原子数)      ← 整数比较，无容差
```

**校验对象是「记录的输出集合」，不是单个产物** —— 这条很关键，见 §④。

### ② 限制试剂 —— **属 A3，不属 A2**

**边界由规则 ⑥（数据与求解分离）直接决定**：A2 提供**每个步骤的输入量与产出量**（化学计量 = 数据），
A3 才去比较"实际有多少 vs 需要多少"、从而算出谁是限制试剂（算法）。
**所以 A2 不需要"限制试剂"这个字段 —— 有它就是越界。**

### ③ 偏移度 δ 的定义（本系统的核心量）

设旋钮 k 的三段为：**最优带 `[lo, hi)`** · **偏移带**（最优带外侧、直到越界为止）· **越界**。

```
δ_k = 0                        若条件落在最优带内
δ_k = 离最优带最近边界的距离      
      ÷ 该侧偏移带的宽度          若落在偏移带内  →  δ_k ∈ (0, 1]
（越界）→ 走【灾难分支】，不走下面的比例式
```

**区间一律取 `[a, b)`（左闭右开）** —— 与 §Edge Cases 一致，避免同一点属于两段。

### ④ 多旋钮合并式（用户拍板：各旋钮独立贡献）

```
主产物占比  =  max(0,  1 − Σ_k δ_k)
副产物占比_k =  δ_k × 该旋钮的副产物系数
```

**约束（导入期硬校验）** —— 补 F-A2-1：

```
对每条记录：   Σ_k 系数_k  ≤  1          ← 因为 δ_k ≤ 1，故 Σ(δ_k × 系数_k) 的最大值为 Σ系数_k
不满足 → 拒绝导入整表 + 指出是哪一条
```

**为什么必须有这条约束**：若 `Σ(δ_k × 系数_k) > 1`，主产物占比会被 `max(0, …)` 夹到 0，
**而副产物仍按各自比例照常产出** → **总产出超过名义量 = 物质凭空多出来**，
与规则 ④（强制配平）直接矛盾。**这条校验的作用是把"凭空造物质"在【导入期】变成一条可见的错误，
而不是等到运行时表现为一个说不清的结果。**

**为什么这个式子能与规则 ④（强制配平）共存**：
③ 与 §Edge Cases 要求**同一输入的各分支区间不重叠、不留缝**，
所以**在任一具体条件下，恰好只有一条记录生效** —— 于是"多旋钮合并"最终仍落在**单条记录**上，
而 ① 的配平校验就作用在这**一条记录的输出集合**（主产物 + 各副产物）上。
**这不是绕过配平，而是"把混合比例也纳入配平校验的对象"。**

### ⑤ 整数量化 —— **归 A3，A2 只存系数**

上面全是**占比**（分数）。把它变成**整数原子**是 A3 的活，
且**必须走 A1 的余数累加器**（`rate_scaled` 指数化整数、`floor` 舍入、误差有界 —— 见 A1 §Formulas）。
**A2 的职责到此为止：它只存"系数"，不存"这一 tick 实际出了几个原子"。**

> **这条边界写清楚，是为了防止一个很自然的越界**：把"本 tick 出 3 个副产物"写进数据表。
> 那会让 A2 变成运行时状态的容器，而 ⑥ 明令数据与求解分离。

### ⑥ 纯度 —— A2 给分子，B2/B3 给分级

**纯度 = 主产物占比**（即 ④ 式里的 `max(0, 1 − Σδ_k)`），**A2 负责提供这个比值**。
但**阈值与分级不属 A2** —— 「≥99.9% 可用 / 99.0–99.9% 需玩家自建分离线 / <99.0% 不可回收」属 **B2/B3**。
**边界**：A2 给一个 0–1 的数，B2/B3 决定这个数意味着什么。

## Edge Cases
七条，**全部由已定的 7 条规则推出来**，不需要再选：

| 边界 | 行为 | 依据 |
|------|------|------|
| **步骤未配平** | **拒绝导入整表 + 指出是哪一条** | ④ |
| **同一组成两个名字** | **结构上不可能** —— 组成式即主键，名字只是显示标签 | ① |
| **条件落在区间边界** | 区间一律取 **`[a, b)`（左闭右开）**，避免同一点同时属于两段 | ③ |
| **条件落在两分支之间（"平局"）** | **结构上应被排除** —— 导入期校验同一输入的各分支区间**不重叠、不留缝** | ③（否则"走哪一支"变成未定义） |
| **循环步骤（A→B→A）** | **A2 允许**（可逆与循环在真实化学里存在，A2 只存事实）；**终止性由 A3 负责** | ⑥ |
| **引用 A1 尚未登记的元素** | **报错并指出"缺的是哪个元素"**（不得静默失败） | 对齐 A1 的 fail-fast 决策 |
| **空组成式 / 某元素原子数为 0** | 拒绝 —— 组成式必须非空，且只记实际存在的元素 | ① |
| **系数预算超限（`Σ系数 > 1`）** | **拒绝导入整表 + 指出是哪一条** | ④（否则总产出超名义量 = 凭空造物质） |

## Dependencies
**上游：A1（唯一）。**

**下游 2 个（A3 · A4）：见 §Interactions with Other Systems 的契约表（本处不重复）。**

> **为什么不重复**：与 A1 同一条理由 —— 同一个事实写在两处就会漂移。
> 本项目已实测过 6 次这类事故。**契约表的唯一权威位置是 §Interactions。**

### 两条由"它是数据"推出的性质（下游会用）

1. **A2 可在引擎之外被测试与校验** —— 配平校验、区间覆盖校验全是**纯函数**（输入是表，输出是"通过/哪一条不通过"）。
   这对 A4（Schema 双解释器）的"两侧一致性"有利：**同一份校验能在 Python 与 GDScript 两侧跑、比对结果。**
2. **任何对 A2 的改动都要按"A3 与 A4 会受影响"来评估** —— 尤其**条件区间的形状**：
   它一变，A3 的求解逻辑跟着变（A3 读的就是这些区间）。

## Acceptance Criteria
**七条，每条都可独立检验。**

| # | 验收项 | 通过标准 |
|---|--------|----------|
| **1** | **配平测试** | 表中每条步骤都通过**整数配平校验**；**故意导入一条未配平的 → 必须拒绝整表并指出是哪一条** |
| **2** | **分支测试** | 同一输入在两组不同条件下**必须能产出不同输出** —— 否则**承重约束 #2 未满足** |
| **3** | **多路径测试** | 至少一个产物存在**两条以上**可达路径 —— 否则**承重约束 #1 未满足** |
| **4** | **区间覆盖测试** | 同一输入的各分支区间**不重叠、不留缝**（否则会出现"平局"或"无人区"，见 §Edge Cases） |
| **5** | **缺元素测试** | 引用 A1 未登记的元素时，必须**报出缺的是哪个元素**（不得静默失败） |
| **6** | **系数预算测试** | 表中每条记录满足 `Σ系数 ≤ 1`；**故意导入一条超预算的 → 必须拒绝整表并指出坏条** |
| **7** | **序列化往返** | 与 A1 同口径：二进制通道必须通过（**值相等且 `typeof()` 仍是 `INT`**）；JSON 通道作为**反例测试，必须失败** |

> **第 2、3 条是本 GDD 特有的**：它们不是通用模板话，而是**把用户的两条承重约束翻译成了测试**。
> **约束不写成测试，就等于没有约束** —— 这是 A1 那轮学到的。

## Visual/Audio Requirements
**A2 作为数据层，无直接视听需求。** 唯一相关项是**副产物的可辨识呈现**：

- **为什么它归这节**：设计的核心意图之一是「**不同错法出不同副产物**」（§Formulas ④）。
  若玩家看不出拿到的是**哪一种**副产物，这个意图就落空了 —— 而那是 **UI/表现问题，不是数据问题**。
- **要求**：副产物出现时必须有**可区分的标识**。
- **约束**：**不得靠"加一种饱和色"来解决** —— `design/art/art-bible.md` §1 把饱和度预算只给了
  **氧气与危险**，§3④ 定的纪律是「**形状优先于颜色**」。所以标识应以**形状 / 图标 / 线型**为主。

## Game Feel
**A2 不承担手感**（手感由 A3 的求解节奏与机器的视听反馈承担）。

但它有一条**间接但关键**的影响：**失败的可读性**。

- 玩家拿到副产物时，应能**从副产物的种类推断出"哪个旋钮错了"** —— 这是 A2 的数据形状决定的
  （见 §Formulas ④：各旋钮独立贡献），**不是 A3 能补出来的**。
- 所以 A2 要给 A3 的**不只是"哪些副产物"**，还要能回答"**这个副产物是哪个旋钮偏了导致的**"。
  —— 这就是为什么规则 ④ 采用"各旋钮独立贡献"而不是"取最差的那一个"：**取最差会让指纹消失。**

**反例**：玩家看到「副产物 +3」但无法归因 → 他只能靠试错穷举五个旋钮 → **那不是难度，是噪音**。

## UI Requirements
**A2 不直接产出 UI** —— 但它是**百科（B4）的数据来源**，而百科是本作新手友好的关键
（用户原话：*「我们并不拒绝一点化学知识都不懂的玩家，我们会提供百科，告诉小白可以怎么提炼、转化、合成产物」*）。

因此 A2 的**数据必须足以让 B4 生成可读条目**，至少包括：

- 化合物的**名称**（显示标签，可由组成式做主键后补）与**组成**
- 它**可能从哪些步骤得到**（可达路径）—— 这直接支撑百科里"小白可以怎么做"那部分
- 每条步骤的**条件带**（最优带 / 偏移带）—— 支撑"条件不对会怎样"的解释

**边界**：A2 只保证"**字段齐全、可被读出**"；**如何组织成给玩家看的文字属 B4**。

> **一条来自本项目的提醒**：A1 的 §UI 已经定了一条要求 —— 用「**投入 / 产出 / 留在系统内**」三列对照表，
> 而**不要**用一个笼统的"守恒 ✅"指示灯。B4 引用 A2 的数据时，应沿用同样的取向：
> **给可核对的细节，而不是给一个结论。**
