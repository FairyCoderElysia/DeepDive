# A2 · 化合物与反应数据表（Compound & Reaction Data Tables）

> **Status**: Draft（骨架 —— 已定的写清，未定的标 `[待定]`）
> **Category**: Core · **Layer**: Foundation · **Priority**: T1
> **Depends On**: **A1**（元素池与计量）—— 化合物的标识符来自元素表
> **被依赖**: **A3 反应求解器** · **A4 Schema 双解释器与契约校验**
> **设计顺序**: 第 2 位（A1 之后；A3/A4 之前）

---

## Summary

存放全项目的**化学事实**：有哪些化合物（其组成 = 元素与原子数）、以及**一个步骤**在什么条件下
能把什么变成什么 —— 但**不负责求解**（求解属 A3）。

## Overview

**它在"数据基座"里的位置**：`systems-index` 明确把基座拆成两半 ——
**A1 是元素，A2 是化合物与反应**，两者共同持有各系统都要引用的数据与 schema；**A3 才求解**。
所以 A2 的产物**是数据，不是算法**。

**它必须满足的两条承重约束**（来自用户原话）：

1. **「每一台机器更像是化学反应中一个或多个步骤，而不是将一个化学反应定死」**
   → 表里存的**不是成品配方**，而是**步骤**。一个产物可以由多条步骤路径达成。

2. **「反应的条件不对，产物纯度不够，都会导致出现意料之外的产物……甚至导致灾难」**
   → 条件（T / P / τ / 催化剂 / 阳极材料）**不是"是否允许"的开关，而是"走向哪一支"的分流器**：
   条件偏离 → 副产物 / 污染 / 灾难通道。**A2 必须能表达分支，而不是只表达"成功"与"失败"。**

**边界（它不是什么）**：
- **不是元素表** —— 那是 A1。
- **不是求解器** —— 那是 A3（限制试剂、化学计量、逐步推进都在 A3）。
- **不是工艺图** —— 那是 A5。
- **不是纯度分级** —— 那是 B2/B3（A2 只提供"哪些副产物会产生"这个事实）。

`[待定 —— 还要写：表的规模量级（先支持多少化合物与步骤？）· 它如何避免"把整张表写死"而留出玩家自行组合的空间 · 典型 tick 下被查询的频率（关系到 A3 的性能）]`

## Player Fantasy

`[待定 —— 方向：A2 是玩家看不见的一层，但它的"丰富度"决定了玩家能感到的"化学是真的"。
服务 P2（严谨是美感）。A1 的玩家感受是"信任"，A2 的可能是"发现"—— 玩家以为自己只是在做水，
却因为条件偏了、得到了一种他没预料到的东西。]`

## Detailed Design

| # | 规则 | 状态 |
|---|------|------|
| ① | **化合物 = 组成式唯一标识**。组成（元素 → 原子数）**就是主键**，名字只是显示标签 —— "同一组成两个名字"在结构上不可能。 | ✅ 已定 |
| ② | **一记录一步骤**：输入（元素 / 化合物 + 数量）→ 条件区间 → 输出（化合物 + 数量）。**分支 = 同一输入的多条记录**，各自带**不重叠**的条件区间 —— **分支不是特例，而是区间划分推出来的。** | ✅ 已定 |
| ③ | **条件语义 = 三段区间**：每个旋钮划分 **最优带 / 偏移带（出副产物）/ 越界（出灾难）**。分立、可测。 | ✅ 已定 |
| ④ | **强制配平**：每条步骤的输入输出**元素原子数必须整数配平**，否则**拒绝导入整张表并指出是哪一条**。 | ✅ 已定 |
| ⑤ | **`schema_version`**：与 A1 同口径（版本化；**迁移机制是 A1/A2 共有的未决项**，见 Open Questions）。 | ✅ 已定 |
| ⑥ | **数据与求解分离**：表是**只读数据**；运行时状态（谁在反应、剩多少、A1 的余数累加器）**一律归 A3**。 | ✅ 已定 |
| ⑦ | **旋钮的权威定义在 A1**：A2 只**引用** `param_*`（见 `design/registry/entities.yaml`），**不得另立定义** —— 否则又是同一事实两处定义。 | ✅ 已定 |

### 三条值得单独写下的推论

- **① 的推论：发现即玩法。** 既然组成式是主键，**玩家可以在不知道名字的情况下造出并发现一个化合物** ——
  这是 P3「连出来的工艺属于玩家」在数据层的落点。名字由百科（B4）后补，**不是前置条件**。
- **③ 的推论：灾难是一个数据区间，不是一段特殊代码。** 把那句「甚至导致灾难」变成**表里可编辑的一格**，
  正是 P2「灾难是内容」的实现方式 —— 灾难若写在代码里，它就只能有开发者预先想到的那几种。
- **④ 的纪律与 A1 一致**：拒绝整表 + 指出坏行（同 A1 的"原子量为 0 时拒绝整表"决策）。
  理由也一样：**一张带着已知错误的数据表看起来和正常的表毫无区别**，而它的下游（A3）会静默地算错。

| 下游 | A2 承诺给它 | **它不得假设** |
|------|-------------|----------------|
| **A3** 反应求解器 | 化合物组成 + 步骤表（含条件窗口与分支） | 不得假设**一个产物只有一条路径**；不得假设**条件只有"对/错"两态** |
| **A4** Schema 双解释器 | 化合物与步骤的 schema + `schema_version` | 不得假设**只有元素表需要版本化**；不得假设**表的形状不会变** |

✅ 已定（口径：`systems-index` 的 `Depends On` 列含 `A2` 的行数 = **2 个** = A3 · A4）。
**写法纪律照抄 A1**：「不得假设」那一列比「承诺」那一列更重要 —— 集成 bug 几乎都出在那里。

## Acceptance Criteria

`[待定 —— 方向：]`
- **配平测试**：表中每个步骤都通过整数配平校验；故意导入一个未配平的步骤必须被拒绝
- **分支测试**：同一个输入在两组不同条件下，必须能产出**不同的**输出（否则承重约束 #2 未满足）
- **多路径测试**：至少一个产物存在**两条以上**可达路径（否则承重约束 #1 未满足）
- **缺元素测试**：引用未登记元素时，必须报出**缺的是哪个元素**（而不是静默失败）
- **序列化往返**：与 A1 同口径（二进制 + 断言类型）
