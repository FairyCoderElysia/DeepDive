# Smoke Test: Critical Paths — 深海工艺（DeepDive: Process）

**Purpose**: 在任何 QA 交接前，15 分钟内跑完这份清单。
**Run via**: `/smoke-check`（读本文件）
**Update**: 每实现一个核心系统就加一条。

> **这份清单是本项目专用的** —— 它的条目全部来自已评审的 26 份 GDD 与 `game-concept.md`，
> **不是通用模板**。每条后面括号里是它的来源（系统编号或概念文档的锚点）。
>
> **判据**：**凡是"设计上必须成立"的东西，都要有一条能被眼睛看出来的检查** ——
> 因为 T1 的目标是**验证那份设计在真机上成立**，而不是"能跑起来"。

---

## A. 启动与基础（永远跑）

1. **游戏能启动到可互动状态**，无脚本错误、无缺失资源报错。
2. **`godot --headless --editor --quit`（= `commands.smoke`）退出码为 0**，且输出里没有 `SCRIPT ERROR`。
3. **场景里没有任何 `Failed to load` / `Unknown class` 报错**（A4 的 class_name 缓存纪律）。

## B. T1 核心链（**本项目的存在理由**）

4. **水电解跑通**：水 → H₂ + O₂，且**原子对账通过**（进多少原子出多少原子，A1 的 ⑤）。
   *（概念文档：前 10 分钟用最浅层的一条链"水电解 → H₂ + O₂"让玩家亲眼看到"条件不同、结果不同"。）*

   **✅ T1 最小切片已可执行（2026-10-03）** —— 不再是一条人工描述，而是一条命令：

   ```bash
   godot --headless --path . scenes/t1_electrolysis.tscn
   ```

   **通过标准**：每一行的 `对账=OK`，且**原子账与化合物账逐元素吻合**。实测基线（t=100）：
   ```
   原子 H=72 O=36 总=108 ｜ 化合物 水×14 H2×22 O2×11 ｜ 对账=OK
   核对：水(H28,O14) + H2(H44) + O2(O22) = H72 O36 ✅
   ```
   ⚠️ **注意它验证的是【两本账】，不是一本**：原子账**守恒**（不变），
   而化合物账**在变** —— 因为 `2H₂O → 2H₂ + O₂` 在原子层面是恒等的。
5. **条件不同结果真的不同**：把**温度 T** 拧离当前点 → **产出或纯度真的变了**。
   *（L1：开局给的旋钮就是温度 T + 催化剂，而玩家此刻会问的正是"条件不同，结果真的会不一样吗？"）*
6. **氧气双角色可感知**：产氧与耗氧**是同一个数字** —— 多造一台机器会**同时**吃掉工业氧与生命维持氧。
   *（B4 的核心规则 ②：不得拆成两个池。）*
7. **氧紧张时三级优先生效**：氧被压到低位时，**生命维持 > 产氧链 > 其他工业**，且**工厂不会永久卡死**。
   *（B4 的 F-B4-1；验收第 3 条"可恢复性测试"。）*
8. **罐子存东西有代价**：往罐里存料 → **罐内非空时持续耗氧**（而不是一次性扣费）。
   *（B4 的验收 5 + B6 的验收 5。）*
9. **存进去再取出来的还是那个东西**：把水存进罐、再取出 → **取回的是水，不是氢氧原子**。
   *（B6 的澄清 1：罐内表示必须是"化合物 → 数量"，不是元素池。）*

## C. 失败与诊断（**"不能是暗算"**）

10. **两条杂质通道可感知且可分辨**：氯污染（猝死）与结垢（慢性）**看起来 / 听起来不同**，
    且**各自的修法不同**（分离 vs 清洗）。
    *（B2 的澄清 1；B10 的六种"停"。）*
11. **灾难可诊断**：制造一次越界 → **必须能查到原因链**（从哪个条件偏移开始、经过哪些环节）。
    *（概念文档："灾难必须可诊断"；B10 的验收 3。）*
12. **灾难可复原**：灾难之后**必须存在一条回到可运行状态的路径**，且代价有限。
    *（B5 的验收 1；概念文档："灾难可复原"是 P2 与 P5 吵出来的设计。）*
13. **失败不是暗算**：任何一次失败，玩家都能在**事前**看到至少一部分后果（预告结果，但不给结论）。
    *（B1 的澄清 2；B7 的澄清 2。）*

## D. 本作独有的那几条（**别的工厂游戏不会有的**）

14. **「连」不是布线，是写反应式**：把一条不该混的物流接到同一入口 → **下游产物真的降档**。
    *（概念文档：核心差异；B1 的验收 2。）*
15. **接错是合法的**：把含污染物流**接回上游** → **必须成功**（且污染雪上加霜），
    **不得弹报错**、**不得阻止**。
    *（B1 的澄清 1：化学错误必须被允许，那是教学内容。）*
16. **纯度规格是硬的**：一件 99.85% 的产物 → **不可用**（而要接分离产线），
    而 99.95% → **可用**。
    *（B3 的澄清 2：全局统一阈值 99.9/99.0；"痕量即毁规格"。）*
17. **热力图默认可用**：开局就能看到一张场（默认**温度**），**且它不占用信号色额度**。
    *（B12 的 ④ 与 ⑧；概念文档："热力图是主图层，不是调试工具"。）*
18. **不看数字就知道自己下去了**（T3 起）：越深画面越暗、越窄、色偏与噪点越重。
    *（B14 的验收 1。）*

## E. 性能与确定性（**P2 的底线**）

19. **同存档 + 同操作序列 → 结果必然复现**（不得有随机性）。
    *（B5 的 ⑨；B19 的验收 4。）*
20. **超预算时世界走慢，而不是降级**：规模做大后 tick 变长，**但每个 tick 仍精确**，
    且**到下限时会告警**（不是硬上限）。
    *（B19 的 ③ 与 澄清 4。）*
21. **界面与音频不跟着世界变慢而"卡"**：走慢时**渲染仍流畅、音频连续但节拍更慢**。
    *（B15 的澄清 3；B11 的 §States。）*

## 怎么用这份清单

- **A + B 每轮必跑**（启动 + 核心链）。
- **C/D 在对应系统实现后加进必跑**。
- **E 在规模测试阶段跑**。
- 任何一条**挂了**，就是一次**设计没落地的证据** —— 而不是"实现有 bug"那么简单：
  **它意味着某份 GDD 里的某条验收，在真机上不成立。**
